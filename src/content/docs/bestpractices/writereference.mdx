Reference（参考手册）是 ORION 操作系统技术文档体系中最严谨、最客观的基石。在企业级业务编排（Business Orchestration）与 Agentic Automation 的语境下，系统行为具有极强的确定性（由合同、规则、资源驱动）。因此，我们的 Reference 文档必须像一份极其严谨的“机器零件图纸”或“食品营养成分表”，容不下任何模糊的描述或营销词汇。

这份规范旨在指导你如何编写符合 ORION 极简、功能主义美学的参考手册。

## 一、 核心定位与隐喻

Reference 提供的是用户在日常工作中随时需要查阅的**命题性或理论性知识（truth and certainty）**。

* **地图（A Map）：** 参考手册就像一张地图。地图只客观描述地形（哪里有山、哪里有河），绝不教你“如何生火”或“应该走哪条路”。
* **食品成分表（Nutritional Information）：** 当你看食品成分表时，你期望看到的是“净重 1000g”、“可能含有微量小麦”。你绝对不希望看到“厨师的烹饪感悟”——在技术文档中，那不仅多余，甚至危险。

**目标受众状态：** 带着明确的问题而来，找到答案（如 API 参数、BPMN 扩展属性的 Key）后立刻离开。

## 二、 ORION 核心编写原则

### 1. 纯粹描述，绝不解释
保持绝对的中立、客观、事实导向。写作中最难的就是“纯粹描述”，请无情剥离多余动作：
* **禁止教学：** 不教用户怎么做，也不解释为什么这么设计。
* **禁止废话：** 遇到想解释原理的冲动，请直接放置指向 How-to（操作指南）或 Explanation（概念解析）的链接。
* **禁止宏大叙事：** 保持谦逊、务实的工程师底色，禁止使用任何过度包装的营销词汇。

### 2. 尊重机器底层的物理结构
文档的层级目录应当直接映射 ORION 操作系统或 Camunda 7 引擎的物理与逻辑结构。顺着代码和架构的逻辑，就是阅读文档的逻辑。

### 3. 标准化语言模式
使用陈述事实、列举清单和发出警告的标准化语言模式。

| 语言模式 | 适用场景 | 示例 |
| :--- | :--- | :--- |
| **陈述事实** | 描述系统默认行为或路径 | ORION Agent 的默认超时配置继承自 Camunda Job Executor。 |
| **列举清单** | 罗列参数、错误码、标志位 | 有效负载 (Payload) 包含以下字段：`agent_id` (String, 必填)。 |
| **严格警告** | 边界条件、限制或危险操作 | 必须使用 HTTPS。除非已通过契约校验，否则绝不可覆盖此参数。 |

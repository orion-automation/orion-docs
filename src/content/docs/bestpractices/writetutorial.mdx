在 Diátaxis 框架中，如果说 How-to guides（操作指南）是帮熟练用户解决当下生产问题的“菜谱”，那么 **Tutorial（教程）则是导师全程陪同并承担最终责任的“学习之旅”**。

在 ORION 企业级操作系统的语境下，教程的终极目标是帮助用户获取技能、熟悉概念并建立信心。它必须让用户在实操中，隐性感受到基于 BPMN 规范的智能体状态流转、规则边界以及资源调配的确定性与威力。

---

## 一、 核心定位与教学契约

Tutorial 的本质是建立一种不对等的**双向契约（The Contract）**：

* **作者（导师）负全责：** 负责决定学什么、怎么学，并**对用户的最终成功负 100% 的责任**。教程路径必须经过极端测试，确保任何用户在任何时候执行都能成功。
* **读者（学徒）零负担：** 读者唯一的责任是“保持专注”并“盲从指令”。读者没有义务在当下理解、记住或推导任何底层逻辑。

### 教程交付的四大硬指标
1. **有意义（Meaningful）：** 让用户在完成后获得切实的成就感。
2. **必成功（Successful）：** 消除一切不确定性，确保 100% 跑通。
3. **逻辑性（Logical）：** 步骤之间的衔接必须符合人类直觉与认知演进顺序。
4. **完整性（Usefully complete）：** 让用户完整经历该功能所涉及的核心动作、概念与工具。

---

## 二、 ORION 核心编写原则与红线

### 1. 极端排斥的“四大反派”

在教程编写中，请克制一切“好为人师”的冲动，严防以下四种极易摧毁学习心流的行为：

:::danger[抽象与泛化 (Abstraction)]
禁止一上来就铺陈宏大的元模型、架构哲学。用户不需要在动手前学习宇宙的起源。
:::

:::danger[长篇大论的解释 (Explanation)]
极度克制解释的欲望。如果必须解释，仅用最基础的语言一句话带过（如：“我们必须在 A 之前执行 B，是因为规则校验的需要”），深度原理一律通过占位链接引导至 Explanation 模块。
:::

:::danger[提供分支选择 (Choices)]
绝对不要给用户分支选项（如“你也可以选择…”）。选择会引发认知过载。必须给定唯一、确定的成功路径。
:::

:::danger[灌输信息 (Information)]
拒绝堆砌与当前具体操作无关的背景知识和参考表单。
:::

### 2. 规范语言原子模式

必须使用第一人称复数，营造导师全程陪同的语境，并随时交付预期反馈（Narrative of the Expected）。

:::tip[正确的导师语境：“我们 (We)”]
**“现在，我们将流程部署到引擎中。”**
确立导师与学徒并肩作战的共同体关系，消除孤立感。
:::

:::caution[错误的独立语境：“你 (You)”]
**“接下来，你需要部署流程。”**
推卸责任，让用户感到孤立无援。
:::

:::tip[正确的成果牵引]
**“在本教程中，我们将共同编排一个自动化合同审查流。”**
明确且具象地展示终局成果，帮助建立全局预期。
:::

:::danger[错误的知识灌输]
**“在本教程中，你将学会如何使用规则引擎。”**
这被 Diátaxis 定义为一种自以为是（presumptuous）的糟糕模式。
:::

:::tip[高频的正向反馈引导]
**“控制台输出应类似于：[INFO] Agent activated。请注意，此时该任务已被引擎自动锁定。”**
尽早且频繁地交付可见结果，并在关键节点引导用户进行环境观察与认知反射。
:::

    使用此 Prompt 确保 AI 扮演严苛的导师角色，剔除所有冗余解释和分支选项。
    
    ```markdown
    # Role
    你是一位世界级、极其挑剔的技术文档专家，精通 Diátaxis 现代技术文档架构组织法中的 "Tutorial" 核心方法论。同时，你对专注于企业级业务编排（Business Orchestration）与 Agentic Automation、核心引擎显式基于 Camunda 7 (BPMN 2.0 编排) 的下一代操作系统（OS）ORION 有着深度的架构和设计认知。

    # Task
    请严格基于 Diátaxis 的 "Tutorial" 哲学，为 ORION 系统的某一具体场景或功能组件，编写一份面向企业级开发者或系统架构师的实操入门教程（Tutorial）。

    # Product Rules (ORION Core Context)
    1. 定位：ORION 是企业级操作系统，基于 Camunda 7，遵循 BPMN 2.0。核心理念是企业运行基于“合同、规则、资源”的显式编排。
    2. 体验：教程必须让用户在实操中，隐性感受到智能体状态流转与资源调配的确定性。
    3. 语调基调：务实、克制、无宏大叙事。

    # Documentation Constraints (Diátaxis "Tutorial" Specification)
    1. 【教学契约】本篇文档是你与读者之间的契约。你对读者的成功负 100% 的责任。步骤清晰无歧义，确保照做 100% 成功。
    2. 【无情消灭四大 temptation】
       - 零选择：不提供任何分支路径（不准出现“或者...”、“你也可以...”）。
       - 零长篇解释：不准在步骤中插入底层原理解释。涉及原理一句话带过，并提供占位链接 `[深入了解底层原理](url)`。
       - 零泛化：只谈当前场景下的具体操作、具体参数。
    3. 【高频反馈与预期叙事】每个动作后必须紧跟系统响应的预期（展示标准输出、日志或 UI 变化），抚平读者的焦虑感。
    4. 【标准语言范式】
       - 必须使用第一人称复数 “我们（We）”。
       - 坚决杜绝“在本教程中你将学到...”，必须使用“在本教程中，我们将共同构建出...”来指明终局成果。
       - 使用强确定性的时序动作祈使句：“首先执行 X。现在，执行 Y。”
       - 关键步骤使用“请注意...”、“让我们检查...”引导观察。
       - 结尾处允许进行克制、委婉的赞赏。

    # Input Information
    - 场景/功能目标：[输入教学目标，如：在 10 分钟内，使用 ORION 编排一个结合企业合同合规规则与大模型 Agent 的自动化流转流程]
    - 前置依赖：[输入依赖，如：已安装本地 ORION Desktop 环境]
    - 核心步骤概述：[输入拆解步骤，如：1. 创建 BPMN 流程；2. 挂载 Agent 节点；3. 一键部署并触发]

    # Output Format
    严格按照以下结构输出教程内容，禁止任何解释性前言：
    ## 1. 概览与最终成果
    [用一小段话告知完成本篇教程后，我们共同构建出的具体成果。严禁出现“你将学到”]
    ## 2. 前置准备 (Prerequisites)
    [极其精简的前置依赖检查清单，确保环境纯净且唯一。]
    ## 3. 详细实操步骤 (The Journey)
    [拆解为 3-5 个核心步骤。每个步骤内部需严格包含：]
    ### 步骤 X: [具体动词开头的强确定性标题]
    - **我们的目标**: [一句话表明本步骤在链路中的位置]
    - **具体执行动作**: [给出绝对正确、唯一的代码块或命令，使用“首先... 现在...”句式]
    - **预期反馈**: [展示执行成功后的日志片段或状态变化]
    - **关键聚焦引导**: [引导用户关注当前的系统状态，如“请注意，此时...”]
    ## 4. 成果复盘与展望
    [客观、克制地描述成果，并给出下一步深入理解概念 (Explanation) 或解决实际问题 (How-to) 的指引链接占位。]
    ```

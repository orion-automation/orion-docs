# 为什么我们需要这样设计流程文档 Agent 的 Prompt？

在构建下一代企业级业务编排系统时，自动化落地的最大痛点往往不在于底层的技术执行，而是 **“业务语言”与“技术实现”之间天然存在的巨大鸿沟**。

为了让 Agent 真正成为业务编排的催化剂，而不是一个只会机械堆砌术语或输出空洞口号的“复读机”，我们为流程文档 Agent 设计了一套具备强咨询思维、边界控制与结构化约束的默认 Prompt。

这份设计并非简单的文本生成模板，而是**连通业务诉求与底层编排引擎的“概念锚点”**。以下是这套 Prompt 背后核心设计理念的深度拆解。

---

## 一、 核心逻辑：打破“业务”与“技术”的语言壁垒

在传统的企业数字化改造中，业务管理层与技术实施团队往往处于“语言不通”的状态：

* **业务管理层**：习惯从战略、价值、效率和合规的角度审视流程。
* **技术实施团队**：需要明确的逻辑边界、责任主体、数据流向以及可直接映射到流程引擎的结构。

如果让大模型自由发挥，它通常会走向两个极端：要么满篇都是“优化管理”的套话，实施团队无从下手；要么直接生成充斥着专业术语的技术草案，业务高管根本无法审阅。

因此，该 Prompt 的首要设计目标是让 AI 充当 **“首席翻译官”**。通过设立“面向业务管理者”与“面向实施团队”的双重视角，Prompt 强制 AI 在顶层管理价值与底层实施抓手之间建立起严密的映射关系，确保输出的方案既能通过高管评审，又能直接作为底层核心引擎（如兼容 Camunda 7 架构的执行中枢）的编排输入。

---

## 二、 关键设计原则的底层原理

### 1. 前置意图路由与边界控制：防发散与精准拆解
在真实的政企或大型商业场景中，客户提供的信息往往是一个宏大的“端到端场景”（如“从采购申请到付款”），其中嵌套了多个跨部门子流程。如果任由大模型自由发挥，极易输出 L3（跨部门协作）与 L4（岗位作业）颗粒度混乱的“大杂烩”文档。

我们在 Prompt 的最前端注入了 **“意图路由与多流程拦截”** 机制：
* **拦截与澄清**：当识别到背景信息中包含多个独立流程时，强制 AI 停止直接生成长篇设计文档，而是先输出一份《潜在流程清单》供用户选择聚焦。
* **特定领域收敛**：这种“先界定边界、后下钻设计”的逻辑，完美契合 ORION 的核心理念——**我们不让大语言模型作为一个无边界的中央中枢盲目狂奔，而是将 AI 严谨地限定在端到端业务流程中的特定领域片段内发挥价值。** 这也为后续流程对接底层引擎的 API 调用（如统一认证集成的 User ID / Group ID 获取）奠定了清晰的任务边界。

### 2. 注入咨询顾问思维：从“反应式回答”转向“主动式诊断”
普通的大模型提示词通常是反应式的。但在复杂的企业业务场景中，客户往往只能描述局部的痛点（如“审批太慢”），无法一眼看清全局的病灶。

Prompt 中注入**咨询顾问思维**的意义在于：
* 拒绝简单的需求复述，强制 Agent 主动诊断流程中潜在的痛点、标准化盲区以及优化方向。
* 明确规定对不确定信息的处理机制：允许做出合理假设，但**必须强制标记“建议确认”**。这杜绝了 AI 面对模糊业务时的盲目编造，保障了企业级流程设计的严肃性。

### 3. 结构化约束：消灭模糊描述，锚定责任主体
“相关人员进行审核”、“按规定处理”这类模糊表述是自动化落地的灾难。在高级的业务编排中，每一个动作、分支判断、输入输出都必须是确定且受控的。

* Prompt 在 **《核心业务步骤》** 与 **《关键决策与审批规则》** 中进行了极其严苛的表格化约束。
* 它强制每一个关键动作必须绑定**责任主体（谁在做）**、**前置条件（什么时候做）**以及**输出结果（产出什么）**。这种结构化输出，为后续无缝转化为底层引擎能够识别的任务流转规则提供了直接依据。

### 4. 预埋自动化基因：精准划定 AI 与人类的边界
一份单纯的文字文档对系统而言是无法直接调用的。Prompt 在结构设计上有意向后延伸，引入了 **《自动化与数字化机会》** 和 **《可复用流程模块》**。

这引导 AI 在设计阶段就自动识别：哪些环节适合交由系统自动化流转，哪些可以沉淀为企业的标准能力资产复用，哪些环节必须保留人类进行关键管理决策。这使得生成的文档直接成为下一代业务编排引擎的可用蓝图。

## 三、 自定义修改指南：如何注入个性化需求？

虽然这套默认 Prompt 已经具备了极高的通用性与专业度，但每个企业的管理文化和合规要求各不相同。我们开放了 Prompt 的自定义权限，建议在以下几个节点进行针对性微调，以贴合实际业务：

:::tip[建议修改与注入的区域]
1. **角色定位调整（`# 角色定位`）**
   * **如何注入**：如果你的企业处于特定强监管行业，可以将角色修改为：“你是一名资深【医疗器械/金融合规】数字化转型顾问”，从而让 AI 的用词更符合行业专有合规语境。
2. **细化行业与场景特征（`# 5. 行业适配`）**
   * **如何注入**：直接追加特定的业务术语库或管理原则。例如：“在分析供应链流程时，必须重点考察【供应商准入池】和【安全库存预警】机制”。
3. **增加特定的输出模块（`# 输出格式`）**
   * **如何注入**：如果实施团队对数据安全有极高要求，可以在格式区新增一个章节：`# 11. 【数据安全与隐私合规】`，要求 AI 必须评估该流程中涉及哪些敏感数据，并给出脱敏建议。
:::

:::danger[自定义修改的“红线”注意事项]
* **切勿破坏前置的“意图路由与边界识别”**：这是防止 AI 产生“幻觉”和“大杂烩输出”的核心闸门。一旦删除，可能导致底层引擎接收到错乱的流程节点。
* **切勿破坏表格化输出结构**：底层的流程解析工具严重依赖“核心业务步骤”和“关键决策规则”的表格来提取要素。如果将这些结构改为了自由文本，方案将无法映射到引擎。
* **保留“不确定信息处理”的约束**：**千万不要**删除“标记需要客户确认的信息”这一条。在企业级业务中，“不知道”远比“一本正经地胡说八道”安全得多。必须利用这个约束把 AI 的发散能力圈定在安全边界内。
* **避免过度前置技术细节**：不要在 Prompt 中强制要求 AI 输出底层组件名称。流程文档的核心价值是业务蓝图，过早引入底层技术名词会破坏文档在业务侧的可读性。
:::

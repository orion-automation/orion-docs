## 1. 读取 XML

SPIN 的 XML 数据格式从字符串或字符流读取并解析 XML。

### 1.1 从字符串读取

在 Java 中把一段 XML 字符串解析成可操作的对象，有两种写法。

* **显式声明格式**：给 `S()` 方法传入 `xml()`，告诉 SPIN 这段内容是 XML。

```java
import static org.camunda.spin.Spin.*;
import static org.camunda.spin.DataFormats.*;

SpinXmlElement xml = S("<order />", xml());
```

* **快捷函数**：直接用 `XML()` 解析。

```java
import static org.camunda.spin.Spin.*;

SpinXmlElement xml = XML("<order />");
```

两种写法得到的是同一类对象。解析时会校验格式，结构不合法（例如标签未闭合）直接抛异常。

### 1.2 从字符流读取

SPIN 支持直接从 `java.io.Reader` 读取，适合处理文件或网络响应，不必先把内容读成字符串。

```java
import static org.camunda.spin.Spin.*;

FileInputStream fis = new FileInputStream("/tmp/incomingOrder.xml");
InputStreamReader reader = new InputStreamReader(fis, "utf-8");
SpinXmlElement xml = XML(reader);
```

也可以写成 `S(reader, xml())`，效果相同。

### 1.3 在脚本语言中读取

脚本语言是动态类型，不需要指明数据格式，SPIN 会自动判別。

```javascript
var orderId = S('<order id="1231" />').attr('id');
```

上面这一行同时完成两件事：解析 XML，以及取出根元素上 `id` 属性的值。

## 2. 节点类型

解析得到的不是一个通用对象，而是按用途分成几类。写代码时选错类型，方法就不存在。

| 类型 | 表示什么 | 常见来源 |
| :--- | :--- | :--- |
| `SpinXmlElement` | 任意 XML 元素 | `XML(...)`、`S(..., xml())` 的返回值 |
| `SpinXmlTreeElement` | 带完整树结构的元素，可增删子元素 | 解析结果、`childElement(...)` |
| `SpinXmlDomElement` | 支持 DOM 层面操作的元素 | 解析结果、`childElement(...)` |
| `SpinXmlAttribute` | 一个属性 | `attr(...)`、`attrNs(...)` |
| `SpinXmlTreeAttribute` | 查询得到的属性 | `xPath(...).attribute()` |
| `SpinList<T>` | 一组节点或属性 | `childElements(...)`、`elementList()` |
| `SpinCollection<T>` | 一组属性或元素 | `attrs()`、`attributes()` |

需要同时用属性与子元素操作时，直接以 `SpinXmlTreeElement` 接收最省事。

## 3. 命名空间

XML 里同名元素可能属于不同命名空间。凡是带 `Ns` 后缀的方法都要求传命名空间 URI；不带后缀的只匹配无命名空间的名称。

| 写法 | 匹配 |
| :--- | :--- |
| `attr("id")` | 只匹配没有命名空间的 `id` |
| `attrNs(uri, "id")` | 匹配指定命名空间下的 `id` |
| `childElement("item")` | 只匹配没有命名空间的 `item` |
| `childElement(uri, "item")` | 匹配指定命名空间下的 `item` |

用错了不会报错，只会取不到东西——这是排查时最容易绕远的一处。

## 1. 描述 (Description)

在 ORION Connect 架构中，引擎提供了一个 `Connectors` 类，用于自动检测类路径 (classpath) 中的所有连接器。架构师和开发人员可以通过指定的连接器 ID (`http-connector`) 获取 HTTP 连接器的底层执行实例。

HTTP 连接器提供了一种无需编写 Java 委派代码，即可在流程中直接发起 REST API 或 HTTP 请求的原生方式。

## 2. Modeler 流程设计器配置映射 (Modeler Configuration)

在实际的 BPMN 业务建模中，HTTP 连接器通常挂载在**服务任务 (Service Task)** 或**发送任务 (Send Task)** 上。其底层通过执行态的输入/输出映射 (Input/Output Mapping) 与上一节提到的泛型 API 进行一一对应。

### 2.1 基础节点配置
在节点属性面板中，必须完成以下声明：
* **Implementation (实现方式)**: 选择 `Connector`。
* **Connector Id (连接器 ID)**: 必须严格填写 `http-connector`。

### 2.2 输入参数映射 (Input Parameters)
通过配置 Input Parameter，向底层的请求对象注入参数：

| 参数名称 (Name) | 变量类型 (Type) | 必填 | 架构与业务说明 |
| :--- | :--- | :--- | :--- |
| **`method`** | `String` | 是 | HTTP 动词，如 `GET`, `POST`, `PUT`, `DELETE` 等。 |
| **`url`** | `String` | 是 | 目标接口地址。支持 `${}` 表达式动态拼接流程变量。 |
| **`headers`** | `Map` | 否 | 请求头字典。常用于注入 `Authorization`, `Content-Type` 或 `Accept`。 |
| **`payload`** | `Text` / `Script` | 否 | 请求体载荷（主要用于 POST/PUT）。若载荷为动态生成的复杂 JSON，建议此处类型选择 `Script` 并结合 SPIN 或 FreeMarker 模板生成。 |

### 2.3 输出参数映射 (Output Parameters)
执行完毕后，底层的响应数据存在于连接器的临时上下文中，必须通过 Output Parameter 将其提取并持久化为流程变量：

| 内部提取变量 | 映射类型 (Type) | 架构与业务说明 |
| :--- | :--- | :--- |
| **`statusCode`** | `String` | 提取 HTTP 响应状态码（如 200, 404）。常用于后续排他网关的业务路由分支判断。 |
| **`response`** | `String` / `Script` | 提取响应体报文。**核心实践**：如果是 JSON 响应，强烈建议此处使用 JavaScript 或 Groovy 脚本 `S(response)` 直接将其转化为 SPIN 对象再存入流程变量。 |
| **`headers`** | `Map` | 提取响应头字典，供有需要的业务链路验证令牌或缓存策略。 |

## 3. Apache HTTP Client 架构集成 (Apache HTTP Client Integration)

HTTP 客户端在底层依赖 Apache HTTP Client 来执行实际的网络请求，并支持所有相应的底层配置选项。

* **默认配置**: 默认情况下，HTTP 客户端使用 Apache 的默认配置，并完全遵守 HTTP Client 支持的标准系统属性。
* **5.x 版本迁移**: 从 Camunda 7.24 版本开始，Connect HTTP 连接器底层升级为使用 Apache HTTP Client 5.x 架构。虽然高层的 Connect API 保持向下兼容，但任何自定义配置和代码扩展都必须迁移使用新的 HttpClient 5.x 包结构（`org.apache.hc.client5.*` 和 `org.apache.hc.core5.*`），以替代旧版的 4.x 包。

## 4. 自定义配置 (Custom Configuration)

如果业务场景需要超越默认配置的功能（例如配置特定大小的连接池或连接管理器），推荐的架构实践是实现并注册一个新的连接器配置器 (Connector Configurator)。

### 4.1 编写配置器类
以下示例展示了如何注入自定义的 `PoolingHttpClientConnectionManager`：

```java
package org.camunda.connect.example;

import org.apache.hc.client5.http.impl.classic.CloseableHttpClient;
import org.apache.hc.client5.http.impl.classic.HttpClients;
import org.apache.hc.client5.http.impl.io.PoolingHttpClientConnectionManager;
import org.camunda.connect.httpclient.HttpConnector;
import org.camunda.connect.httpclient.impl.AbstractHttpConnector;
import org.camunda.connect.spi.ConnectorConfigurator;

public class HttpConnectorConfigurator implements ConnectorConfigurator<HttpConnector> {

  public Class<HttpConnector> getConnectorClass() {
    return HttpConnector.class;
  }

  public void configure(HttpConnector connector) {
    PoolingHttpClientConnectionManager connectionManager = new PoolingHttpClientConnectionManager();
    connectionManager.setDefaultMaxPerRoute(10);
    connectionManager.setMaxTotal(200);

    CloseableHttpClient client = HttpClients.custom()
      .setConnectionManager(connectionManager)
      .build();
    ((AbstractHttpConnector) connector).setHttpClient(client);
  }
}

```

### 4.2 注册 SPI (Service Provider Interface)

为了让引擎自动检测到这个新的配置器，必须在项目资源目录下的 `META-INF/services/org.camunda.connect.spi.ConnectorConfigurator` 文件中，声明该配置器类的全限定名。

## 5. 底层请求构建与执行 (Requests via API)

在 Java 环境或自定义组件中直接调用时，HTTP 连接器提供了一套流式 API。它不仅支持 GET 和 POST，还完整支持 PUT、DELETE、PATCH、HEAD、OPTIONS 和 TRACE 等 HTTP 动词。

### 5.1 创建 HTTP 请求

* **简单 GET 请求**:
```java
http.createRequest()
  .get()
  .url("[http://camunda.org](http://camunda.org)")
  .execute();

```


* **带 Payload 的 POST 请求**:
```java
http.createRequest()
  .post()
  .url("[http://camunda.org](http://camunda.org)")
  .contentType("text/plain")
  .payload("Hello World!")
  .execute();

```



### 5.2 添加自定义请求头 (Headers)

可以通过 `.header()` 方法向 HTTP 请求中注入自定义的请求头。

```java
HttpResponse response = http.createRequest()
  .get()
  .header("Accept", "application/json")
  .url("[http://camunda.org](http://camunda.org)")
  .execute();

```

## 6. HTTP 响应错误处理 (Error Handling)

在默认架构下，HTTP 连接器在调用期间遇到 4XX（客户端错误）或 5XX（服务器错误）状态码时，**不会**自动抛出异常。

为了在不需要编写额外脚本逻辑的情况下激活错误阻断机制，可以通过 `configOption` 方法（或在 Modeler 中配置 Input Parameter）将 `throw-http-error` 属性强制设置为 `TRUE`。开启该选项后，一旦遇到 HTTP 响应错误，引擎将直接抛出异常，从而可以触发挂载在任务边界上的 BPMN 错误事件。

```java
HttpResponse response = http.createRequest()
  .get()
  .configOption("throw-http-error", "TRUE")
  .url("[http://camunda.org](http://camunda.org)")
  .execute();

```

## 7. 响应处理 (Response)

执行请求后返回的响应对象中，包含了 HTTP 状态码、响应头字典以及响应体报文。

```java
Integer statusCode = response.getStatusCode();
String contentTypeHeader = response.getHeader("Content-Type");
String body = response.getResponse();

```

**架构规范**: 在 Java 代码中成功处理完业务响应后，必须显式调用 `response.close()` 方法关闭底层连接以释放 I/O 资源（如果是在 BPMN 模型中通过参数映射使用，引擎会自动处理资源释放）。

## 8. 泛型 API (Generic API)

除了专用的流式方法外，连接器还提供了一套底层的泛型 API，允许通过动态传参的方式设置请求或提取响应。这也是 Modeler 中 Input/Output 映射的底层依托。

### 8.1 请求泛型设置

```java
HttpRequest request = http.createRequest();
request.setRequestParameter("method", "GET");
request.setRequestParameter("url", "[http://camunda.org](http://camunda.org)");
request.setRequestParameter("payload", "hello world!");

```

### 8.2 响应泛型提取

```java
response.getResponseParameter("statusCode");
response.getResponseParameter("headers");
response.getResponseParameter("response");

```

## 1. 描述 (Description)

事件网关（Event-based Gateway）允许流程基于**外部事件**（而非内部流程变量数据）来决定执行分支。

在 ORION 平台中，排他网关（XOR）和包容网关（OR）依赖于引擎瞬间计算变量得出路由结果；而事件网关则是一个**显式的等待状态 (Wait State)**。当执行流到达事件网关时，流程会彻底挂起，引擎将静默等待未来某个特定事件的发生（例如：等待客户回复邮件、等待外部系统回调，或等待设定的超时时间到达）。最先发生的事件将赢得路由权。


## 2. 拓扑结构与连接约束 (Topology & Connection Rules)

事件网关在 BPMN 规范中拥有最严苛的拓扑连接限制。它的输出连线在物理本质上是用来声明“事件订阅”的，因此必须遵循以下绝对规则：

| 约束类型 | 事实描述与架构限制 |
| :--- | :--- |
| **分支基数** | 一个事件网关**必须**拥有两个或更多的输出顺序流（Outgoing Sequence Flows）。 |
| **目标节点类型** | 事件网关的输出连线**只能**连接到**中间捕获事件 (Intermediate Catch Event)**（例如：定时器、消息、信号事件）。在当前的引擎实现中，不支持直接连接到接收任务 (Receive Task)。 |
| **目标节点入度** | 连接到事件网关后游的中间捕获事件，**必须且只能**拥有一条唯一的输入连线（Incoming Sequence Flow）。不允许其他节点的分支直接汇入这些捕获事件。 |
| **条件屏蔽** | 事件网关的输出连线上**绝对不能**配置任何条件表达式（Condition Expression）。路由完全由事件的触发决定。 |


## 3. 执行生命周期与竞速行为 (Execution & Racing Behaviors)

事件网关的核心物理行为被设计为一场“只能有一个赢家”的竞速游戏。

### 3.1 到达与挂起 (Suspension & Subscription)
当执行流（Token）到达事件网关时：
* 引擎会立即 **挂起（Suspend）** 当前的流程执行。
* 引擎会沿着网关的所有输出连线扫描，并为每一个相连的中间捕获事件**创建底层事件订阅 (Event Subscriptions)**。例如，如果网关连接了一个 10 分钟的定时器和一个“报警”信号事件，引擎会同时向内部定时器作业表和信号总线注册监听。

### 3.2 触发与竞速法则 (The Racing Condition)
* **先到先得 (First-to-fire wins)**：网关会一直阻塞，直到这批被订阅的事件中有一个被触发。
* **孤立连线陷阱**：在引擎底层，从事件网关连接到捕获事件的这些顺序流**从未被真正“执行”过**。它们的作用仅仅是帮助引擎确定需要订阅哪些事件。真正的执行流是从被触发的那个捕获事件**之后**才重新开始流动的。

### 3.3 自动取消机制 (Automatic Cancellation)
这是事件网关保证流程状态机不被污染的核心机制：
* 一旦有**任何一个**事件被触发并赢得了竞速，引擎将立即放行该分支。
* 同时，引擎会自动且强制地 **取消（Cancel）** 该网关产生的所有其他未被触发的事件订阅。例如，如果“报警”信号在 3 分钟时触发了，那个 10 分钟的定时器订阅将被引擎底 层的垃圾回收机制直接销毁，确保不会在未来发生灵异的超时触发。


## 4. 引擎级技术属性 (Engine Execution Properties)

以下属性决定了事件订阅与唤醒在底层数据库事务中的边界。

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 强制切断数据库事务。当执行流到达网关时，将创建事件订阅的动作交由异步 Job 处理。 |
| **Async After** | Boolean | `false` | 强制在离开网关前切断数据库事务。 |
| **Exclusive** | Boolean | `true` | （需配合 Async）确保异步作业的独占执行。 |

:::tip[最佳实践：经典的超时控制模式]
在微服务或 Agent 编排中，事件网关最经典的用途是 **“带有超时的外部调用等待”**。
将事件网关的一个分支连接到**消息捕获事件 (Message Catch)** 用于等待正常回调，另一个分支连接到**定时器捕获事件 (Timer Catch)** 设置超时时间（如 `PT10M` 代表 10 分钟）。如果 10 分钟内外部未响应，定时器触发，自动取消消息订阅并引导流程进入异常升级链路。
:::

## 1. 描述 (Description)

基于数据的排他网关（Data-based Exclusive Gateway，通常简称 XOR 网关）用于在流程中创建分支路径（Alternative Paths）。

在 ORION 平台强调**基于确定性规则与资源**的企业级业务运行理念中，排他网关是执行严格逻辑判断的枢纽。它不进行任何模糊的意图推断，而是基于当前流程实例中的精确数据（Variables），严格评估预设的条件表达式，确保执行流（Token）有且仅有一条合规的路径继续流转。


## 2. 核心属性定义 (Core Property Definitions)

排他网关自身的属性相对简单，其核心控制逻辑实际分布在关联的输出顺序流（Outgoing Sequence Flows）上。

| 属性名称 (UI Label) | 对应 XML 属性 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **默认流 (Default Flow)** | `default` | Sequence Flow ID | **强烈推荐配置**。当所有输出分支的条件都不满足时，引擎将自动选择的兜底路径。在画布中通常用带有一条短斜线的箭头表示。 |

### 2.1 输出顺序流的条件定义 (Outgoing Flow Conditions)
对于连接在排他网关下游的每一条顺序流，必须明确配置路由规则（除非该流被指定为默认流）。

| 属性名称 (UI Label) | 对应 XML 标签/属性 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **条件类型 (Condition Type)** | `<conditionExpression xsi:type="...">` | 枚举 | 决定求值方式，默认为 `Expression`（表达式），也可切换为 `Script`（脚本）。 |
| **条件表达式 (Condition Expression)** | `<conditionExpression>` | JUEL / Script | 返回布尔值（`true` / `false`）的表达式公式。例如 `${orderAmount >= 10000}`。 |


## 3. 分支与汇聚行为约束 (Routing & Converging Behaviors)

排他网关在拓扑结构中承担分流（Diverging）和汇聚（Converging）两种截然不同的物理行为。

### 3.1 分流行为 (Diverging)
当执行流到达网关时，引擎会拦截并评估所有输出顺序流上的条件。
* **唯一命中法则**：引擎会选择**第一个**条件评估为 `true` 的顺序流。即便在数据上存在多个分支条件同时满足的情况，执行流也**只会**走向第一个被命中的分支，其他的将被直接抛弃。
* **评估顺序的随机性**：在 BPMN 规范与 ORION 引擎底层，**不保证**分支条件的评估顺序（通常依赖于底层 XML 节点的解析顺序）。因此，设计时必须确保各分支条件在逻辑上是**绝对互斥**的，避免产生不可预测的路由结果。
* **无路可走的异常 (No Path Exception)**：如果没有任何一个分支条件返回 `true`，且该网关**未配置默认流 (Default Flow)**，ORION 引擎将抛出底层的 `ProcessEngineException`，直接阻断当前数据库事务，并在控制台生成一个运维事故（Incident）。

### 3.2 汇聚行为 (Converging)
排他网关也可以用于将多条独立的互斥分支重新合并为一条主干。
* **直通机制 (Pass-through)**：作为汇聚网关使用时，它**不具备任何同步或等待能力**。
* **系统行为**：每当一个 Token 从任意一条输入连线到达汇聚排他网关时，它会瞬间穿过网关，直接进入下游的输出连线。**警告**：如果因为上游设计失误，导致多条并行分支同时到达了一个 XOR 汇聚网关，网关会将它们依次全部放行，这将导致下游的业务节点被多次重复执行。


## 4. 引擎级技术属性 (Engine Execution Properties)

以下属性决定了路由判断在底层数据库事务中的执行边界。

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 强制切断数据库事务。若开启，条件评估将由后台 Job Executor 异步执行。 |
| **Async After** | Boolean | `false` | 强制在离开该网关前切断数据库事务。 |
| **Exclusive** | Boolean | `true` | （需配合 Async）确保同一流程实例的异步 Job 不被并发拾取。 |

:::tip[架构师准则：防范无路由死锁]
在设计复杂的企业决策流（如基于动态外部数据的审批路由）时，请务必为每一个排他网关显式配置**默认流 (Default Flow)**。这不仅是防范脏数据导致流程引擎异常崩溃的最后一道防线，更是规范化业务异常兜底（如路由到“人工异常处理岗”）的最佳实践。
:::

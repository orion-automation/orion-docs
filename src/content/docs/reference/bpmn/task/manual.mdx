## 1. 描述 (Description)

手工任务（Manual Task）用于定义完全在流程引擎控制范围之外执行的工作任务。

在 ORION 平台中，它专门用于对那些引擎既不需要感知其具体执行者，也不涉及任何底层系统交互或用户界面（UI）接口的纯线下物理动作进行建模（例如：仓库人员进行实物装车、纸质文件的物理归档等）。

## 2. 业务语义与底层执行机制 (Business Semantics & Execution)

手工任务在业务表达与底层引擎的物理执行之间存在显著的行为差异。

### 2.1 业务架构语义
在业务流程模型（BPMN）层面，带有手型图标的手工任务能够清晰地向业务架构师和系统分析师传达：流程流转至此处时，存在一段必须由人工在线下完成的实际工作步骤。

### 2.2 引擎透传行为 (Pass-through Activity)
在 ORION 引擎底层的状态机执行中，手工任务被严格处理为一个**透传活动 (Pass-through Activity)**。
当执行流（Token）到达手工任务时，引擎**不会**在数据库中创建任何待办任务记录，也**不会**产生任何等待挂起状态（Wait State）。引擎状态机会在瞬间自动越过该节点，直接沿着输出顺序流继续向下游推进流程。

## 3. 引擎级扩展属性与约束 (Engine Extensions & Constraints)

尽管手工任务在底层是瞬间透传的，但引擎依然支持为其配置标准的执行上下文扩展属性，以便在节点前后进行数据隔离或事务切分。

| 属性名称 (UI Label) | 对应 XML 扩展 | 约束与事实描述 |
| :--- | :--- | :--- |
| **异步边界 (Async)** | `camunda:asyncBefore` / `camunda:asyncAfter` | 强制切断数据库事务边界。将瞬间的透传动作交由后台异步队列处理。 |
| **独占排他 (Exclusive)** | `camunda:exclusive` | 仅在 `camunda:asyncBefore` 或 `camunda:asyncAfter` 为 `true` 时生效。确保同一流程实例的异步任务不被并发交叉拾取。 |
| **任务优先级** | `camunda:jobPriority` | 决定其在异步队列中的执行权重。 |
| **重试策略** | `camunda:failedJobRetryTimeCycle` | 设定异步执行失败（例如 I/O 映射异常）时的重试间隔与次数。 |
| **输入输出映射 (I/O)**| `camunda:inputOutput` | 用于在执行流穿过该节点时，对流程变量进行局部读取、计算或赋值。 |

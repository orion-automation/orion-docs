## 1. 描述 (Description)

脚本任务（Script Task）是一种完全自动化的系统活动。当执行流（Token）到达该节点时，引擎底层将自动执行与之绑定的脚本代码。

在 ORION 平台中，脚本任务是快速实现轻量级数据转换、路由逻辑前置计算以及简单 API 调用的核心组件，它极大地避免了为微小逻辑编写繁重 Java 类的开销。


## 2. 核心架构约束与脚本引擎 (Core Constraints & Scripting Engines)

脚本任务的物理定义强依赖于 `script`（代码内容）和 `scriptFormat`（语言标识）这两个核心属性。

* **JSR-223 兼容契约**：`scriptFormat` 的值必须是与 JSR-223（Java 平台脚本规范）完全兼容的名称。为了使用特定的脚本引擎，必须确保对应的 jar 包已加载至系统类路径（Classpath）中。
* **支持的语言矩阵**：ORION 引擎底层（Camunda 7）在架构上支持大多数 JSR-223 兼容的引擎。目前官方经过严格集成测试的核心语言包括：Groovy, JavaScript, JRuby 以及 Jython。
* **代码注入方式**：脚本源码可以直接作为文本内容嵌入在 XML 的 `<script>` 子元素中；对于复杂的企业级脚本，也支持通过表达式或外部资源（External Resource）进行解耦引用。


## 3. 变量穿透与底层作用域 (Variable Scoping & Context)

在脚本执行的生命周期内，引擎为执行流提供了一个完全开放的数据上下文。

### 3.1 全量读取与显式写入
* 到达该脚本任务的执行流（Execution）所能访问的**所有流程变量**，都可以直接在脚本内部无缝使用。
* 例如，如果在代码中直接遍历 `inputArray`，它实际上引用的正是底层的同名流程变量。
* 脚本内部可以通过调用 `VariableScope` 接口提供的 `execution.setVariable("key", value)` 方法，将运算结果强制回写至全局流程上下文中。

### 3.2 自动存储机制 (Auto-Storing) 与物理限制
引擎配置中提供了一个名为 `autoStoreScriptVariables` 的全局开关。
* **行为契约**：开启后，引擎会自动将脚本中所有的全局变量存储为流程变量。
* **防污染声明**：如果开启了此功能，但业务上不希望某些局部变量被持久化（例如计数器 `sum`），必须使用 `def` 关键字（如 `def sum = 0`）进行局部隔离声明。
* **架构级警告 (Groovy Only)**：该自动存储机制**仅对 Groovy 语言提供可靠支持**。如果强行在其他语言中开启，引擎无法保证最终导出哪些变量；例如，Ruby 引擎绝对不会导出任何脚本变量。
* **保留字冲突**：在编写脚本时，绝对禁止使用以下引擎底层保留名称：`out`, `out:print`, `lang:import`, `context`, `elcontext`。


## 4. 返回值映射与多实例并发陷阱 (Result Variables & MI Trap)

除了使用 `setVariable`，更符合规范的做法是通过 `camunda:resultVariable` 属性来捕获脚本的最终返回值。

* **覆盖契约**：脚本的最终执行结果会被赋值给指定的变量名；如果该变量已存在，底层值将被直接覆盖。如果没有配置该属性，脚本的返回值将被系统底层安全忽略。
* **多实例并发灾难 (MI Overwrite Trap)**：如果在一个多实例（Multi-instance）子流程或多实例任务中配置了 `resultVariable`，每一次子任务完成时，都会对该同名变量执行一次覆写。在并发环境下，这会导致极为严重的“随机值覆盖”现象。



## 5. 引擎级技术属性 (Engine Execution Properties)

脚本任务支持以下 ORION 引擎底层扩展属性，以保证长耗时脚本不会拖垮主业务线程：

| 属性名称 (UI Label)      | 对应 XML 扩展                                             | 约束与事实描述                                                             |
| :----------------------- | :-------------------------------------------------------- | :------------------------------------------------------------------------- |
| **异步边界 (Async)**     | `camunda:asyncBefore` / `camunda:asyncAfter`              | 强制切断数据库事务。对于包含重度计算的脚本，强烈建议开启。                 |
| **独占排他 (Exclusive)** | `camunda:exclusive`                                       | （仅当开启 Async 时生效）确保异步 Job 不被多线程交叉拾取，防范乐观锁异常。 |
| **任务重试与优先级**     | `camunda:failedJobRetryTimeCycle` / `camunda:jobPriority` | 决定异步队列权重，以及脚本异常时的自动重试策略。                           |
| **输入输出映射 (I/O)**   | `camunda:inputOutput`                                     | 用于在脚本执行前后，对变量进行更细粒度的隔离映射。                         |
| **外部资源 (Resource)**  | `camunda:resource`                                        | 支持引入外部存储的脚本文件。                                               |

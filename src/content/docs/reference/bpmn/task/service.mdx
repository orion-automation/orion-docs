## 1. 描述 (Description)

服务任务（Service Task）是执行自动化业务逻辑的活动节点。

在 ORION 平台底层的执行态中，服务任务将流程状态机与实际的系统行为进行桥接。根据企业架构的解耦要求，架构师可以通过属性面板灵活配置其底层是通过引擎内同步执行，还是通过跨系统异步轮询来实现业务逻辑的调用。

## 2. 属性面板 Implementation 配置 (Implementation Settings)

在 ORION 建模器的属性面板中，`Implementation` 设置是决定服务任务底层执行逻辑的核心。通过切换 `Type` 选项，将直接改变底层生成的 XML 属性与执行行为：

### 2.1 Java Class (Java 类)
* **底层映射**：生成 `camunda:class` 属性。
* **使用方法**：在输入框中，必须填入实现了 `JavaDelegate` 或 `ActivityBehavior` 接口的类的全限定名（例如 `com.orion.bpm.delegate.OrderProcessDelegate`）。引擎在运行时将通过反射同步实例化该类并执行逻辑。

### 2.2 Delegate Expression (委派表达式)
* **底层映射**：生成 `camunda:delegateExpression` 属性。
* **使用方法**：填入能够解析为委派对象的 JUEL 表达式（例如 `${orderProcessDelegate}`）。在企业级 Spring 环境中，这是实现依赖注入与服务解耦的标准实践，引擎将直接从 Spring Context 中获取对应的 Bean 并执行。

### 2.3 Expression (表达式)
* **底层映射**：生成 `camunda:expression` 属性。
* **使用方法**：填入用于执行特定方法或返回计算值的表达式（例如 `${myService.doWork()}`）。此模式通常配合面板中的 `Result Variable` 属性使用，将方法的计算结果直接回写至流程上下文中。

### 2.4 External (外部任务)
* **底层映射**：生成 `camunda:type="external"` 属性。
* **使用方法**：选择此项后，面板将强制要求填写 `Topic`（主题）。执行流到达时，引擎不会主动执行逻辑，而是将任务发布到底层队列，由外部工作节点（Worker）通过 REST API 异步轮询拾取处理。

### 2.5 Connector (连接器)
* **底层映射**：生成 `<camunda:connector>` 扩展子元素。
* **使用方法**：选择此项后，需要配置 `Connector Id`（如 `http-connector` 或 `soap-http-connector`），并通过输入输出参数（Input/Output）配置发起网络请求所需的 URL、Method、Headers 和 Payload。

## 3. 泛型委派与字段注入 (Field Injection)

当 `Implementation` 类型选择为 `Java Class` 或 `Delegate Expression` 时，可以结合属性面板中的 `Field Injections`（字段注入）功能提升代码复用率。
* **机制**：在面板中定义字段名称及其对应的字符串值或表达式。引擎在实例化 Java 类时，会自动将这些模型级别的值注入到类的成员变量中，从而允许通过同一个 Java 类处理不同的业务参数。

## 4. 跨系统解耦：外部任务机制 (External Tasks)

当 `Implementation` 类型选择为 `External` 时，服务任务采用跨越系统和技术栈边界的异步调用模式。

### 4.1 物理轮询机制 (The Polling Pattern)
执行流到达声明为“外部”的服务任务后会挂起，引擎会将一个工作项（Work Item）持久化到底层队列中。独立的外部工作节点（可使用任意编程语言实现）主动通过 REST API 向引擎轮询获取指定 `Topic` 的任务，执行完毕后再通过 API 回调通知引擎继续推进流程。

## 5. 返回值映射与多实例覆写行为 (Result Variables & MI Behavior)

当 `Implementation` 类型选择为 `Expression` 时，引擎允许将计算结果存入流程变量上下文中。

* **结果变量 (`Result Variable`)**：指定一个变量名（如 `myVar`）。节点完成时，表达式的返回值将被写入该变量。如果流程中已存在同名变量，原有值将被覆盖。若未指定此属性，返回值将被系统忽略。

:::caution[多实例并发覆写风险 (Multi-Instance Overwrite Risk)]
如果在多实例（Multi-instance）结构（例如多实例子流程或声明了多实例循环的服务任务自身）中配置了 `Result Variable`，底层状态机会在**每一个独立的子实例完成时**执行一次变量覆写。在并发执行环境下，这将导致最终流程变量的值不可预测。
:::

## 6. 引擎级扩展属性与依赖约束 (Engine Extensions & Constraints)

服务任务在底层具有严格的 XML 配置依赖关系。一个合法的服务任务，**必须且只能**包含一种 Implementation 策略。

| 扩展属性 | 依赖条件 | 事实描述 |
| :--- | :--- | :--- |
| `camunda:resultVariable` | 仅在使用 `Expression` 时有效。 | 不能用于 Class 或 Delegate 模式（这些模式应通过 Java 代码内部 `execution.setVariable()` 处理数据）。 |
| `camunda:topic` | 仅在 `External` 时可用。 | 用于定义外部任务的订阅通道。 |
| `camunda:taskPriority` | 仅在 `External` 时可用。 | 决定该外部任务在轮询队列中的优先级权重。 |
| `camunda:errorEventDefinition`| 仅作为 `External` 的子元素时有效。 | 用于定义外部任务的错误处理规范。 |
| `camunda:exclusive` | 仅在 `camunda:asyncBefore` 或 `camunda:asyncAfter` 为 `true` 时生效。 | 确保同一流程实例的异步任务不被多线程交叉并发拾取。 |

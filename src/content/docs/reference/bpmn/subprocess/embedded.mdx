## 1. 描述 (Description)

嵌入式子流程（Embedded Subprocess）是一种复合型活动（Compound Activity），它在内部封装了其他的活动、网关和事件，从而在父级主流程中形成一个完整的、局部的业务执行闭环。

在 ORION 平台处理极度复杂的企业业务链路时，嵌入式子流程不仅用于实现逻辑上的模块化降维，更重要的是，它在底层的执行状态机中创造了一个**全新的独立作用域（Scope）**，为局部变量隔离与精准的异常/事件拦截提供了物理边界。



## 2. 核心架构约束 (Core Architectural Constraints)

与普通的任务节点不同，嵌入式子流程具有极度严苛的内部拓扑与连线法则。违反以下任何一条，ORION 引擎在部署编译阶段将直接抛出异常。

| 约束类型 | 事实描述与架构限制 |
| :--- | :--- |
| **唯一的启动入口** | 内部**必须且只能**包含一个**空开始事件 (None Start Event)**。绝对不允许使用任何触发型开始事件（如消息、定时器、错误或信号开始事件）来启动嵌入式子流程。 |
| **强制的完结出口** | 内部**必须至少**包含一个结束事件。尽管 BPMN 2.0 理论规范允许省略开始和结束事件，但 ORION 引擎为了保证状态机生命周期的严谨性，强制要求显式建模结束节点。 |
| **连线物理隔离墙** | 顺序流（Sequence Flows）**绝对禁止跨越子流程的物理边界**。外部的连线只能连接到子流程的边界框上，不能直接穿透连入其内部节点；同理，内部节点也不能直接连线到子流程外部。数据的流转必须依赖全局变量或输入/输出（I/O）映射。 |


## 3. 核心能力：层级建模与事件作用域 (Capabilities)

### 3.1 视觉与逻辑降维 (Hierarchical Modeling)
* **折叠状态 (Collapsed)**：在顶层画布上，子流程可以被折叠（显示为一个带有 `+` 号的圆角矩形），从而向业务架构师隐藏底层的复杂细节，提供端到端的宏观视角。
* **展开状态 (Expanded)**：展开后，暴露出内部完整的执行链路，供研发人员进行具体节点的属性配置。

### 3.2 局部事件作用域 (Event Scoping)
这是嵌入式子流程在架构设计中最具价值的特性。**子流程为其内部执行的活动圈定了一个专属的事件监听生命周期。**

* **边界监听机制**：当执行流（Token）进入子流程时，附加在子流程外边界上的事件（如边界定时器、边界消息或错误）被激活；当 Token 成功离开子流程时，这些边界监听器被自动销毁。
* **隔离拦截**：例如，在“准备晚餐”的子流程边界上附加一个“收到外出就餐邀请”的边界消息事件。**只有当流程正处于“准备晚餐”这个子流程内部的任何一个步骤时**，收到邀请才会中断做饭。如果处于“准备晚餐”之前的步骤，或已经进入“吃晚餐”的步骤，该邀请消息将被系统安全地忽略，不会引发状态机的错乱。



## 4. 变量快照与数据上下文 (Variable Context)

作为一个独立的作用域，嵌入式子流程对流程变量具有特殊的读写行为：

* **向下穿透**：子流程内部的节点默认可以读取父级主流程中的所有全局变量。
* **局部作用域**：可以在子流程内部通过属性面板配置 `Input/Output` 映射，或者通过内部代码创建仅在该子流程生命周期内存活的**局部变量 (Local Variables)**。这些局部变量对子流程外部不可见。
* **补偿快照**：如《取消与补偿事件》文档所述，当子流程成功完成时，引擎会为其内部的局部变量拍摄一张冻结快照，供未来的补偿处理器使用。



## 5. 引擎级技术属性 (Engine Execution Properties)

除了标准的并发控制，子流程还支持重试策略与数据映射扩展。

| 属性名称 (UI Label) | 对应 XML 扩展 | 约束与事实描述 |
| :--- | :--- | :--- |
| **Async Before/After** | `camunda:async*` | 强制切断数据库事务。当进入或离开庞大的子流程域时，建议开启以切断主事务，防止长事务超时锁死数据库。 |
| **Exclusive** | `camunda:exclusive` | 确保同一流程实例的异步 Job 不被交叉并发拾取。 |
| **Job Priority** | `camunda:jobPriority` | 决定当子流程被异步执行时，其在后台 Job 队列中的优先级权重。 |
| **Retry Time Cycle** | `camunda:failedJobRetryTimeCycle` | 定义当子流程初始化失败（如 I/O 映射异常）时的重试间隔与次数（例如 `R3/PT5M` 代表每 5 分钟重试 1 次，共 3 次）。 |
| **Input/Output** | `camunda:inputOutput` | 用于显式声明子流程需要从全局上下文中提取哪些变量进入局部作用域，以及完成时向全局暴露哪些运算结果。 |

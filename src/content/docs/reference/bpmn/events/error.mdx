## 1. 描述 (Description)

错误事件（Error Events）用于在流程模型中显式定义和处理偏离“快乐路径（Happy Path）”的异常分支。

在 ORION 的架构编排中，错误事件是处理业务阻断契约（如：合同审批被硬性否决、库存锁定失败）的核心机制。它通过向上层作用域（Scope）抛出特定的错误代码（Error Code），触发预设的补偿或异常处理流。


## 2. 架构边界：业务错误 vs. 技术异常 (Business vs. Technical Errors)

在 ORION 引擎的底层设计哲学中，必须严格区分以下两种错误类型。**BPMN 错误事件仅用于处理业务错误。**

* **业务错误 (Business Errors)**：属于业务逻辑的一部分。例如“客户信用评级过低”、“所选 IoT 设备已离线”。这类错误应该被 BPMN Error Event 捕获，并引导执行流走向特定的业务处理分支（如向客户发送拒绝通知）。
* **技术异常 (Technical Exceptions)**：属于系统运行时的不可控灾难。例如 Java `NullPointerException`、网络超时、数据库死锁或 OOM。这类异常**默认不由** BPMN 错误事件处理，而是触发引擎底层的 Job 重试机制（Retries），并在多次失败后转化为控制台的事故记录（Incident），交由运维人员人工干预。


## 3. 核心定义属性 (Core Error Definitions)

在 BPMN 属性面板中，抛出与捕获错误的契约映射依赖于以下全局定义：

| 属性名称 (UI Label) | 对应 XML / 扩展 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **错误名称 (Error Name)** | `name` | String | 错误在系统中的人类可读标识符（如 `Credit Check Failed`）。 |
| **错误代码 (Error Code)** | `errorCode` | String | **核心路由契约**。引擎根据此 Code 将抛出的错误精准匹配到对应的捕获事件（如 `ERR_CREDIT_001`）。 |
| **错误消息 (Error Message)** | `errorMessage` | String | （可选）附加的文本说明，可在抛出时携带，用于为捕获端提供更详细的上下文。 |

### 3.1 捕获端的局部变量映射 (Error Variable Mappings)
对于**错误捕获事件（Catch/Boundary）**，引擎允许将捕获到的异常元数据转化为当前作用域的局部变量。
* **Error Code Variable**: 指定一个变量名，用于接收捕获到的 `Error Code`。
* **Error Message Variable**: 指定一个变量名，用于接收捕获到的 `Error Message`。


## 4. 节点级应用行为与约束 (Contextual Behaviors)

### 4.1 错误开始事件 (Error Start Event)
用于在特定的子作用域内拦截抛出的错误。
* **顶级流程级 (Top-level Process)**：**绝对禁止**。顶级流程不能由错误启动。
* **事件子流程级 (Event Sub-process)**：完全支持。用于处理父作用域内发生的错误。**必须是中断型（Interrupting）**，即错误一旦触发，父级主流程将立即终止。
* **标准嵌入式子流程 (Embedded Sub-process)**：**绝对禁止**。

### 4.2 错误中间捕获事件 (Error Intermediate Catch Event)
* **支持度**：**绝对禁止**。BPMN 2.0 规范中不存在“中间捕获错误”的定义。捕获错误必须依托于边界事件或事件子流程。

### 4.3 错误边界事件 (Error Boundary Event)
依附于任务（如 User Task, Service Task）或子流程的边界，捕获其内部抛出的错误。
* **中断特性**：**永远为中断型（Interrupting）**。BPMN 规范不允许非中断的错误处理。一旦捕获到错误，主任务/子流程将被强制销毁。
* **全局捕获 (Catch-all)**：如果属性面板中未绑定具体的 `Error Code`（留空），该边界事件将充当“万能捕获器”，拦截其依附节点内部抛出的**任何** BPMN 错误。

### 4.4 错误结束事件 (Error End Event)
向当前执行流抛出指定的 BPMN 错误。
* **传播行为**：当执行流到达错误结束事件时，当前分支结束。引擎会**逐层向上（冒泡）**搜索匹配该 `Error Code` 的边界事件或事件子流程。


## 5. 未捕获的 BPMN 错误 (Unhandled BPMN Error)

当错误结束事件抛出了一个 BPMN 错误，但整个流程的各级父作用域中都没有定义能够捕获它的边界事件或事件子流程时，将触发引擎的兜底机制。

* **默认系统行为**：引擎默认会**记录该信息（Log information）并静默结束当前的执行流（End execution）**。这种静默结束可能会导致业务链条异常断裂而未发出警报。
* **严格模式配置 (Strict Configuration)**：为了防止业务异常被静默吞没，ORION 推荐通过引擎配置开启严格模式。当在流程引擎配置或部署描述符中设置 `enableExceptionsAfterUnhandledBpmnError = true` 时，遇到未捕获的 BPMN 错误，引擎将抛出底层的 `Process Engine Exception`，阻断当前数据库事务，并在 ORION Cockpit 中生成一个显式的运维事故（Incident）。


## 6. 引擎级技术属性 (Engine Execution Properties)

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 强制切断数据库事务，由 Job Executor 异步接管。 |
| **Async After** | Boolean | `false` | 强制在离开该节点前切断数据库事务。 |
| **Exclusive** | Boolean | `true` | （需开启 Async）确保同一流程实例的异步 Job 不被并发拾取。 |

## 1. 描述 (Description)

升级事件（Escalation Events）用于在流程执行期间，向上层作用域（Scope）报告一种“需要更高层级关注或协助，但未必阻断当前工作”的业务状态。

在 ORION 平台的分层架构编排中，升级事件是实现**子父流程跨层通信**的核心机制。它通常用于处理 SLA 超时预警、需要额外人工介入的辅助审批、或是非致命性的业务降级通知。


## 2. 架构边界：升级 (Escalation) vs. 错误 (Error)

企业级架构师在建模时，必须严格区分升级事件与错误事件的物理行为边界：

* **错误事件 (Error)**：**致命且永远中断。** 一旦抛出，当前主任务或子流程必须立即销毁。适用于“合同验证失败且无法挽回”的场景。
* **升级事件 (Escalation)**：**具备弹性，支持非中断模式。** 抛出升级后，当前正在执行的子流程或任务**可以继续运行**，同时唤醒上层作用域的并行处理流。适用于“当前 Agent 仍在尝试处理，但已耗时过久，需通知主管知晓”的场景。


## 3. 核心定义属性 (Core Escalation Definitions)

在属性面板中，升级事件的通信契约依赖于以下全局定义与局部映射：

| 属性名称 (UI Label) | 对应 XML / 扩展 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **升级名称 (Escalation Name)** | `name` | String | 人类可读的业务标识符（如 `SLA Warning`）。 |
| **升级代码 (Escalation Code)** | `escalationCode` | String | **核心路由契约**。引擎根据此 Code 逐层向上冒泡匹配捕获事件。若留空，则匹配上层拦截所有升级的“万能捕获器”。 |

### 3.1 捕获端的局部变量映射 (Escalation Variable Mappings)
对于**升级捕获事件（Catch/Boundary）**，引擎允许将捕获到的代码转化为当前作用域的局部变量。
* **Escalation Code Variable**: 指定一个变量名，用于在捕获端接收传递上来的 `Escalation Code`，常用于在一个万能边界事件中进行后置的动态路由判断。


## 4. 节点级应用行为与约束 (Contextual Behaviors)

### 4.1 升级中间抛出事件 (Escalation Intermediate Throw Event)
用于在流程主干中显式抛出升级信号。
* **系统行为**：当执行流到达此节点时，引擎向父级作用域抛出指定的 `Escalation Code`。
* **非中断延续**：抛出动作完成后，**当前执行流不会被销毁**，而是继续沿输出连线 (Outgoing Sequence Flow) 正常向下执行。

### 4.2 升级结束事件 (Escalation End Event)
* **系统行为**：当执行流到达时，抛出指定的 `Escalation Code`，随后**终结当前这一条执行流（Token）**。
* **注意**：它仅终结到达该节点的特定分支。如果该事件位于子流程内，它向上级抛出升级信号后，子流程内的其他并行分支不受影响。

### 4.3 升级边界事件 (Escalation Boundary Event)
依附于调用活动（Call Activity）或子流程（Sub-process）的边界，捕获其内部抛出的升级信号。
* **非中断型 (Non-interrupting, 推荐/默认)**：捕获升级信号后，主任务/子流程继续执行。引擎从该边界事件派生出一条额外的并行分支，用于处理上报的事件。
* **中断型 (Interrupting)**：捕获升级信号后，强制销毁主任务/子流程（此模式下，其物理行为与 Error Boundary Event 完全一致）。

### 4.4 升级事件子流程开始事件 (Escalation Start Event for Event Sub-process)
用于在特定的作用域内部署专属的升级响应逻辑。
* **支持度**：完全支持。同样区分**中断型**与**非中断型**。
* **顶级流程级限制**：**绝对禁止**作为顶级流程的启动入口。升级事件仅在执行流的上下级嵌套结构中具有意义。


## 5. 冒泡路由与未捕获处理 (Bubbling & Unhandled Escalations)

* **层级冒泡 (Hierarchical Bubbling)**：当升级事件被抛出时，ORION 引擎会从当前作用域开始，**逐层向外（向上）** 搜索匹配的边界事件或事件子流程。一旦被某一层成功捕获，冒泡即刻停止。
* **未捕获的升级 (Unhandled Escalation)**：如果升级信号冒泡至最顶层流程域仍未被任何节点捕获，**引擎不会抛出异常，也不会阻断流程**。该未捕获的升级信号将被静默丢弃（仅在 DEBUG 日志中留存），主流程继续正常执行。


## 6. 引擎级技术属性 (Engine Execution Properties)

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 强制切断数据库事务。对于抛出事件，建议开启，以防止上层处理逻辑的异常回滚导致当前子流程抛出动作失败。 |
| **Async After** | Boolean | `false` | 强制在离开该节点前切断数据库事务。 |
| **Exclusive** | Boolean | `true` | （需配合 Async）确保同一流程实例的异步 Job 不被并发拾取。 |

:::tip[跨系统解耦最佳实践]
在微服务编排中，如果子流程 A 需要向父流程 B 报告进度或预警，使用**非中断的升级抛出事件**结合父流程的**非中断升级边界事件**，是最优雅的设计。它避免了使用全局 `Signal Event` 导致的广播污染，同时保持了父子生命周期的强绑定结构。
:::

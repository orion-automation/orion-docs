## 1. 描述 (Description)

信号事件（Signal Events）用于在流程引擎内部或跨异构系统实现**发布-订阅（Publish-Subscribe）**模式的全局广播通信。

与消息事件（点对点、携带特定实例契约）不同，信号是一种未定向的全局通知。当一个信号被触发（抛出）时，引擎中所有正在监听该信号的捕获节点都会同时被唤醒并作出响应。在 ORION 平台的资源编排中，信号抛出不仅传递状态，还可以通过显式的**变量映射传播 (In Mapping Propagation)** 机制，严格控制当前实例的业务资源向全局广播通道的流转。


## 2. 核心定义属性 (Core Signal Definitions)

在 BPMN 属性面板中，信号的设计契约分为基础标识定义与数据传播映射两个核心配置区。

### 2.1 基础属性
| 属性名称 (UI Label) | 对应 XML / 扩展 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **信号名称 (Signal Name)** | `name` | String | **必填**。引擎进行广播匹配的全局标识符。允许通过表达式在运行时动态解析。 |

### 2.2 信号抛出变量传播属性 (Variable Propagation & Mappings)
仅针对**信号中间抛出事件**与**信号结束事件**。面板在物理与逻辑上被划分为两个独立的控制域：全局传播策略与逐项映射策略。

#### A. 全局传播策略 (In mapping propagation)
控制是否将当前上下文中的海量变量进行一键广播。
| 属性名称 (UI Label) | 对应 XML 属性 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **Propagate all variables** | `camunda:in variables="all"` | Boolean | 开启后，引擎会将当前作用域内的所有变量全量深拷贝，注入到信号广播的 Payload 中。 |
| **Local (作用域隔离)** | `local="true"` | Boolean | （仅当开启 Propagate all 时生效）开启后，**仅广播当前执行流（Execution）的局部变量**，主动屏蔽流程实例级别的全局变量，防止敏感全局资源泄露。 |

#### B. 逐项映射定义 (In mappings)
用于显式声明特定变量的提取与转换规则。可与全局策略叠加使用（用于覆盖特定变量名）。
| 属性名称 (UI Label) | 对应 XML 属性 | 格式/选项 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **Type** | - | `Source` \| `Source Expression` | 决定输入源是纯静态变量名，还是需要动态计算的 JUEL 表达式。 |
| **Source** | `source` \| `sourceExpression`| String | 源变量名或表达式（如 `${order.amount * 1.2}`）。 |
| **Target** | `target` | String | 广播上下文中接收该数据的目标变量名。 |
| **Local (提取隔离)** | `local="true"` | Boolean | 开启后，引擎在解析 `Source` 时，强制仅在当前局部执行流中查找，不会向上层父域或全局域回溯穿透。 |


## 3. 节点级应用行为与约束 (Contextual Behaviors)

### 3.1 信号开始事件 (Signal Start Event)
用于监听特定信号，一旦信号广播，自动实例化全新的流程。

* **顶级流程级 (Top-level Process)**：当引擎内部抛出或 API 触发匹配的 `Signal Name` 时，将自动创建该流程的一个新实例。
* **事件子流程级 (Event Sub-process)**：当父级流程运行期间捕获到该信号时触发。支持**中断型**（销毁主流程）和**非中断型**（派生并行分支）。

### 3.2 信号中间捕获事件 (Signal Intermediate Catch Event)
充当执行流（Token）的全局监听等待状态。执行流到达此节点后将被挂起。一旦引擎中该信号被广播，**所有**处于此监听状态的实例都将被唤醒并继续前进。

### 3.3 信号边界事件 (Signal Boundary Event)
依附于任务的边界，监听全局环境状态的变化。
* `true` **(中断型)**：收到信号后，立即销毁主任务。
* `false` **(非中断型)**：收到信号后，主任务继续保留，派生并行执行流。

### 3.4 信号中间抛出 / 结束事件 (Signal Throw / End Event)
当执行流到达抛出节点时，引擎会自动查找全局所有订阅了该 `Signal Name` 的有效处理器，并同步分发该信号。针对信号抛出时的变量载荷（Payload），系统行为遵循以下合并契约：

1.  **全量广播优先**：若勾选了 `Propagate all variables`，所有当前域变量将率先装载入广播通道。
2.  **局部作用域锁**：任何勾选了 `Local` 的传播或映射动作，都会触发引擎的作用域拦截器，严格拒绝向上层作用域（Scope）越权读取变量，这是构建企业级多租户/多分支隔离流的关键机制。
3.  **显式映射覆盖**：在 `In mappings` 中定义的规则将被最后执行。如果映射的 `Target` 名称与全量广播中的变量名冲突，显式映射的值将强行覆盖全量广播中的旧值。


## 4. 运行时集成提示 (Runtime API Integration)

除了在 BPMN 流程内部通过抛出事件触发信号外，外部系统也可以通过 ORION 接口向引擎广播信号。在调用 API 时，允许附加全局变量载荷，这些变量将被统一注入到所有响应该信号的流程实例中。

具体 API 调用参数及载荷注入规范，请参阅流程开发集成技术文档：`[API 参考手册：Signal Event / 信号广播]`。


## 5. 引擎级技术属性 (Engine Execution Properties)

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 强制切断数据库事务，由 Job Executor 异步接管。 |
| **Async After** | Boolean | `false` | 强制在离开该节点前切断数据库事务。 |
| **Exclusive** | Boolean | `true` | （需开启 Async）确保同一流程实例的异步 Job 不被并发拾取，防止乐观锁异常。 |

:::caution[广播风暴与事务级联崩溃陷阱]
当使用信号抛出事件（Signal Throw）时，引擎默认会在**同一个数据库事务**中同步唤醒所有匹配的捕获节点。如果当前有海量实例正在监听该信号，引擎将尝试在一个事务内处理所有实例的状态变更与变量投递，这极易导致数据库锁超时和系统级 OOM。

**最佳实践**：当预期订阅者数量不可控时，必须在对应的**信号捕获事件 (Catch Event)** 上强制勾选 `Async Before`。这会将广播动作与执行动作在物理层解耦，将庞大的并发唤醒与变量注入任务打散到 Job Executor 异步队列中平滑处理。
:::

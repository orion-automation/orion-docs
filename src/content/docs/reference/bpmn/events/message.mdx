## 1. 描述 (Description)

消息事件（Message Events）用于在独立的参与者（不同的 BPMN Pool）之间，或外部异构系统（如 IoT 传感器、外部大模型 Agent）与 ORION 流程引擎之间，进行显式的异步通信。

在 ORION 的资源编排哲学中，消息不仅是触发信号，更是携带业务载荷的通信契约。


## 2. 核心定义属性 (Core Message Definitions)

在 BPMN 流程设计阶段，属性面板仅关注消息在模型层的静态基础定义。

| 属性名称 (UI Label) | 对应 XML / 扩展 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **消息名称 (Message Name)** | `name` | String | **必填**。引擎进行消息匹配的基础标识符。允许通过表达式（如 `${sensorAlert}`）在运行时动态解析。 |

### 2.1 唯一性约束与高级订阅路由 (Uniqueness & Correlation)

在 BPMN 静态建模层面，`Message Name` 是最基础的标识符，但 ORION 引擎底层对 BPMN 2.0 标准的消息订阅机制进行了强大的关联扩展：

*   **开始事件的全局唯一性**：对于**顶级流程的消息开始事件**，其 `Message Name` 在当前租户的所有已部署流程定义中**必须全局唯一**。引擎需要依赖此唯一名称来明确判断应当实例化哪个具体的业务流程。
*   **捕获事件的高级定向路由**：对于运行中的**消息中间捕获事件**或**边界事件**，允许海量流程实例同时监听同一个 `Message Name`。引擎在运行时，能够根据外部系统传入的 **业务主键 (Business Key)、流程实例 ID (Process Instance ID) 或特定的流程变量 (Variables)**，将消息精准定向投递（Correlate）到唯一指定的等待实例中。

:::tip[运行时集成提示]
在 BPMN UI 设计器中不涉及具体的定向载荷映射。上述提到的业务主键映射、实例 ID 定向投递以及 JSON 消息载荷 (Payload) 注入，均属于运行时的 API 集成契约。
关于外部系统如何利用这些高级扩展字段进行消息订阅触发，请参阅流程开发集成技术文档：`[API 参考手册：Message Correlation / 消息触发]`。
:::


## 3. 节点级应用行为与约束 (Contextual Behaviors)

### 3.1 消息开始事件 (Message Start Event)
用于通过接收特定消息来实例化一个全新的流程，或触发一个事件子流程。

*   **顶级流程级 (Top-level Process)**：
    *   **系统行为**：当引擎 API 收到匹配的 `Message Name` 时，自动创建一个新的流程实例。
    *   **支持度**：完全支持。一个流程定义允许包含**多个**不同的消息开始事件。
*   **事件子流程级 (Event Sub-process)**：
    *   **系统行为**：当父级流程实例运行期间接收到消息时触发。支持**中断型**（中断主流程运行）和**非中断型**（派生并行分支）。
*   **标准嵌入式子流程 (Embedded Sub-process)**：
    *   **支持度**：**绝对禁止**。引擎不承认标准子流程边界内的消息开始事件。

### 3.2 消息中间捕获事件 (Message Intermediate Catch Event)
充当执行流（Token）的显式等待状态（Wait State）。

*   **系统行为**：执行流到达此节点后将被挂起，引擎持久化当前事务。直到引擎接收到匹配该事件通信契约（包含 Message Name 及相关的关联维度）的消息时，执行流才会被唤醒并继续前进。

### 3.3 消息边界事件 (Message Boundary Event)
依附于任务（如 User Task、Service Task）的边界，用于捕获任务执行期间的外部异步干预。

*   **特有属性（Cancel Activity）**：
    *   `true` **(中断型)**：收到消息后，立即销毁当前主任务，执行流沿边界连线离开（例如：人工审批期间，收到来自其他系统的“申请已撤销”消息）。
    *   `false` **(非中断型)**：收到消息后，主任务继续保留，引擎派生出一条并行的执行流处理消息响应。

### 3.4 消息中间抛出 / 结束事件 (Message Throw / End Event)
向外部系统或另一个流程发送消息。

*   **实现契约 (Implementation Required)**：在 Camunda 7 引擎底层，BPMN 引擎不会自动将抛出的消息路由给其他捕获事件。消息抛出事件**必须配置具体的实现逻辑**（如委托类、脚本或具体的执行工作流机制），将其转化为实际的系统通信动作。


## 4. 引擎级技术属性 (Engine Execution Properties)

以下属性决定了事件在触发时的物理事务边界。

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 强制在处理该消息事件前切断数据库事务。对于抛出事件，强烈建议开启，避免外部通信阻塞引擎主线程。 |
| **Async After** | Boolean | `false` | 强制在离开该消息节点前切断数据库事务。 |
| **Exclusive** | Boolean | `true` | （需开启 Async）确保同一流程实例中的异步 Job 不会被多个线程并发拾取。 |

:::tip[最佳实践]
在基于事件驱动的微服务与 Agent 交互中，利用 `Message Intermediate Throw Event` 向外部系统发送业务指令，随后紧跟一个 `Message Intermediate Catch Event` 等待其异步回调，是构建健壮的、跨系统长时异步业务流（Long-Running Transactions）的最标准架构范式。
:::

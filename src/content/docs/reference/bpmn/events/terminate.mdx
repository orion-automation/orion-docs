## 1. 描述 (Description)

终止结束事件（Terminate End Event）是一种具有强氧化性的特殊结束节点。

在 BPMN 2.0 标准规范中，普通的结束事件（None End Event）仅会消耗到达该节点的当前执行流（单个 Token）。然而，当一个 Token 到达终止结束事件时，引擎会立即触发生命周期销毁机制，**无条件终止当前作用域（Scope）内的所有并行分支与活动实例**。

在 ORION 平台中，它是处理一票否决、紧急熔断或多路并行流提前收敛的核心控制组件。


## 2. 核心配置属性 (Core Properties)

在静态建模层面，终止结束事件的属性极其精简，其物理核心在于包含一个 `<terminateEventDefinition>` 标签，界面上通常没有复杂的业务参数映射。

| 属性名称 (UI Label) | 对应 XML 标签 | 数据类型 | 事实描述与默认行为 |
| :--- | :--- | :--- | :--- |
| **元素编号 (ID)** | `id` | String | **必填**。引擎内的唯一节点物理标识。 |
| **元素名称 (Name)** | `name` | String | （可选）人类可读的业务名称。 |


## 3. 核心机制：多层级作用域边界 (Scope of Impact)

终止结束事件的“毁灭范围”严格受限于它在 BPMN 模型中所处的**作用域边界（Scope）**。理解以下两者的行为差异，是避免企业级工作流意外熔断的关键。

### 3.1 顶级流程域作用域 (Top-level Process Scope)
当终止结束事件放置在顶级主流程（Top-level Process）的主干或并行分支上时：
* **引擎物理行为**：一旦触发，引擎将立即强行销毁**整个流程实例（Process Instance）**。
* **影响范围**：此时，流程中所有正在并行的分支（Parallel Gateways 衍生流）、处于挂起状态的异步任务（User Task、Message Catch Event）、以及正在运行中的子流程实例，都将被一并强制终结。流程实例状态直接流转至 `COMPLETED`。

### 3.2 嵌套子流程作用域 (Sub-process Scope)
当终止结束事件放置在**嵌入式子流程（Embedded Sub-process）**或**事件子流程（Event Sub-process）**内部时，引擎将触发局部作用域拦截：
* **引擎物理行为**：它**仅会终结当前子流程域**内部的所有活动。子流程内部的其他并行 Token 会被全部销毁，随后整个子流程宣布结束。
* **影响范围（不向上击穿）**：Token 将沿着子流程的唯一输出连线（Outgoing Sequence Flow）正常流出，继续执行父级流程的后续节点。**父级流程中与该子流程并行的其他主干分支完全不受影响。**


## 4. 引擎级技术属性 (Engine Execution Properties)

以下属性决定了终止动作在底层数据库事务与线程池中的执行边界。

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before** | Boolean | `false` | 若勾选，Token 抵达该节点后，终止动作将交由 Job Executor 异步批量执行，防止同步销毁海量并行节点导致主线程阻塞。 |

:::tip[最佳实践]
在复杂的企业级编排场景中（例如：多方 Agent 并行联合征信，只要其中一家 Agent 返回“高风险欺诈”，则立刻终止整个征信链路），将 `Terminate End Event` 配合 `Parallel Gateway` 或 `Sub-process` 使用，是构建高效熔断与提前收敛机制的最优架构范式。
:::

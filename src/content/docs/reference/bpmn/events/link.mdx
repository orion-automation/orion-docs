## 1. 描述 (Description)

链接事件（Link Events）是一种纯视觉维度的流程路由机制，旨在替代长距离的顺序流（Sequence Flow）连线。

在 ORION 平台的复杂企业级编排中，如果一个主流程包含数十个节点，跨越整个画布的物理连线会导致“面条式（Spaghetti）”的混乱拓扑。链接事件充当了流程图中的 **“GoTo”语句**，允许执行流（Token）从画布的一端“瞬移”到另一端，从而保持模型的极简与高可读性。

**核心架构事实**：链接事件**没有任何运行时（Runtime）物理开销或状态驻留**。在 ORION（Camunda 7）引擎解析 BPMN XML 时，配对的链接事件会被直接编译并等效替换为一条普通的物理顺序流。


## 2. 核心链接定义契约 (Core Link Definitions)

在属性面板中，链接事件的配对完全依赖于唯一的名称映射。

| 属性名称 (UI Label) | 对应 XML / 扩展 | 数据类型 | 事实描述与约束 |
| :--- | :--- | :--- | :--- |
| **链接名称 (Link Name)** | `name` | String | **必填**。充当路由通道的唯一标识符。抛出端与捕获端的 `Name` 必须完全一致才能成功配对。 |


## 3. 节点级应用行为与结构约束 (Contextual Behaviors)

链接事件仅包含中间抛出和中间捕获两种形态，且对其结构拓扑有着极其严苛的基准约束。

### 3.1 链接中间抛出事件 (Link Intermediate Throw Event)
充当虚拟连线的起点（出口）。
* **基数约束**：一个捕获事件可以对应**多个**抛出事件（多对一汇聚）。
* **唯一抛出约束**：一个抛出事件**绝对只能**对应一个捕获事件（一对一映射）。如果存在多个同名的捕获事件，引擎将在部署编译阶段直接抛出错误。

### 3.2 链接中间捕获事件 (Link Intermediate Catch Event)
充当虚拟连线的终点（入口）。
* **入度约束**：作为虚拟链路的接收端，该节点**不允许**有任何物理输入连线（Incoming Sequence Flow）。
* **执行行为**：由于其本质是物理连线，执行流到达捕获节点后**不会发生任何挂起或等待**，直接无缝向下游继续流转。


## 4. 作用域硬性边界 (Scope Boundaries)

链接事件的最大架构限制在于其**不可跨越作用域**。

* **同级可见性 (Same Scope Only)**：配对的抛出与捕获事件**必须位于同一个 BPMN 作用域层级**。
* **隔离规则**：
    * **禁止跨子流程**：绝对禁止使用链接事件将 Token 从父流程直接抛入子流程（Sub-process），或从子流程内部直接抛出到父流程。若需跨越子流程边界，必须使用标准的输入/输出顺序流。
    * **禁止跨池 (Cross-Pool)**：绝对禁止使用链接事件在不同的参与者（Pools）之间传递控制权。池间通信必须使用消息事件（Message Events）。


## 5. 引擎级技术属性 (Engine Execution Properties)

由于引擎在解析时将链接事件等效视为顺序流（Sequence Flow），因此它们在运行时不具备独立的高级事务切断能力。

| 属性名称 (UI Label) | 数据类型 | 默认值 | 约束与事实描述 |
| :--- | :--- | :--- | :--- |
| **Async Before/After** | Boolean | `false` | **强烈不建议配置**。由于链接事件仅代表一根虚拟连线，在此处强行切断数据库事务缺乏业务语义。如果需要异步延续，请将其配置在链接事件下游的实际任务节点（如 Service Task）上。 |

:::tip[审计与历史追踪]
由于链接事件在引擎编译阶段即被“扁平化”处理，因此在 ORION 运行时的历史数据库表（History Tables）以及执行流追踪（Audit Trails）中，**不会留下任何链接事件被触发的记录**。运维人员在审计实例时，看到的将是一条从上游任务直接抵达下游任务的物理执行轨迹。
:::

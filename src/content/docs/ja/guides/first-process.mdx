<p class="lead">
  このチュートリアルでは、私たちは実際に動くビジネスプロセスを一緒に作ります。ワークスペースの作成から始め、キャンバス上のプロセス図を仕上げ、エンジンへデプロイして 1 回実行するところまで進みます。コードは一行も書きません。
</p>

## 1. 全体像と最終成果

通る道は 7 ステップです。

| ステップ | やること | 終わったときに手元にあるもの |
| :--- | :--- | :--- |
| 1 | ワークスペースを作成する | 業務アプリが 1 つ入ったワークスペース |
| 2 | ワークスペースを開く | その中の業務アプリ一覧 |
| 3 | 業務アプリを開く | 設計とディスカバリーの作業台 |
| 4 | プロセスを新規作成する | プール・レーン・開始イベントが揃ったキャンバス |
| 5 | プロセスを描く | 分岐があり、つながったプロセス |
| 6 | エンジンへデプロイする | エンジン上のデプロイ記録 |
| 7 | 実行を開始する | 実際に動いているプロセスインスタンス |

因果ははっきりしています。**ワークスペースが業務アプリを入れ、業務アプリがプロセスを入れ、デプロイされたプロセスだけが実行できる。** この一本の線を覚えておけば、どこをクリックするかで迷いません。

## 2. はじめる前に

<Aside type="note" title="前提条件">

- ORION にログイン済みで、「デザイン」モジュールを開けること
- ワークスペースを作成する権限があること

「デザイン」を開いたときに「このアカウントには自分のワークスペースがありません」と表示される場合、アカウントの設定がまだ整っていません。ORION の運用担当者に連絡してください。以降のステップは進められません。

</Aside>

## 3. 手順

### ステップ 1: ワークスペースを作成する

**このステップの目的**

入れ物を用意します。ワークスペースはこの製品で最も外側の枠で、業務アプリ、プロセス、フォーム、コネクタはすべてその中に入ります。

**実行する操作**

1. 「デザイン」モジュールを開き、「マイワークスペース」を表示します。
2. 右上の `ワークスペース作成` をクリックします。
3. ダイアログの **ワークスペース名** に、たとえば「受注フルフィルメント」と入力します。
4. 同じダイアログに **初期業務アプリ名** もあります。最初の業務アプリをここで作ってくれる項目で、既定値は「業務プロセスアプリ」です。そのままにします。
5. `作成` をクリックします。

**確認できること**

ダイアログが閉じ、一覧に作成したワークスペースが表示されます。コラボレーター欄には自分のアカウントが入っています。同時に「業務プロセスアプリ」という業務アプリもその中に用意されています。

**ここに注目**

業務アプリを別途作成するステップは**ありません**。初めて使う人が 1 手減らせるように、ワークスペースの作成と同時に最初の 1 つを用意する設計です。以降のプロセスはすべてこの業務アプリの下にぶら下がります。

### ステップ 2: ワークスペースを開く

**このステップの目的**

作成した入れ物の中に入り、中身を確認します。

**実行する操作**

一覧で、いま作成したワークスペースの名前をクリックします。

**確認できること**

ワークスペースの詳細画面に切り替わり、「業務アプリ」タブに「業務プロセスアプリ」の行が表示されます。

**ここに注目**

一覧の列は中身の要約です。業務アプリ数、コラボレーター、作成日時、最終更新日時。前回使ったワークスペースかどうかは、最終更新日時を見るのが一番早い判断材料になります。

### ステップ 3: 業務アプリを開く

**このステップの目的**

業務アプリの中に入り、リソースの構成を確認します。

**実行する操作**

「業務プロセスアプリ」の行をクリックします。

**確認できること**

左側に `ディスカバリー`、`デザイン`、`実行` の 3 セクションからなるツリーが現れ、右側が作業領域になります。

**ここに注目**

3 つのセクションは 3 種類の仕事に対応します。`ディスカバリー` は現状把握の素材と結論、`デザイン` はこれから描くもの、`実行` はエンジンにデプロイ済みのプロセスです。既定では 3 つとも展開されています。閉じている場合はセクションの見出しをクリックすれば開きます。

### ステップ 4: プロセスを新規作成する

**このステップの目的**

プール、レーン、開始イベントが最初から入っているキャンバスを手に入れます。

**実行する操作**

`デザイン` セクションでプロセスを置くフォルダーを探し、作業領域の空状態カードにある `新規プロセス` をクリックします。

**確認できること**

キャンバスが開き、プールが 1 つ、その中にレーンが 1 本、レーンの左端に「開始」という開始イベントが表示されます。

<Aside type="tip" title="観察ポイント">

プロセスを置くフォルダーは、この画面で 2 つの名前を持ちます。既定の **設計ビュー** では「ブループリント」、**開発ビュー** に切り替えると「オーケストレーション」です。同じフォルダー、同じファイルで、呼び方がビューに追随するだけです。見つからないときは、まず左下の現在のビューを確認してください。

</Aside>

### ステップ 5: プロセスを描く

**このステップの目的**

この図を、本当に動くプロセスに仕上げます。タスク、分岐、終了があり、すべての図形がつながっている状態です。

**実行する操作**

1. キャンバス左上のモデリングパレットで `タスク` をクリックし、レーン内の開始イベントの右側に配置します。
2. 同じパレットから `排他ゲートウェイ` を選び、タスクの右側に配置します。
3. 承認側の次のステップとして `タスク` をもう 1 つ配置します。
4. タスクの後に `終了イベント` を配置します。
5. 開始イベント右端のコネクタからタスクへドラッグし、続く図形も順につなぎます。分岐は、ゲートウェイの左右からそれぞれ 1 本ずつ線を出します。

**確認できること**

キャンバス右下のチェックリストが順に埋まります。プール、レーン、開始イベント、終了イベント、タスク、ゲートウェイ、そして最後に「すべてのノードがつながっている」。すべて埋まれば、このプロセスは完成です。

**ここに注目**

チェックリストはチュートリアルの飾りではなく、製品側の判定そのものです。**チェックリストが全部緑になって初めて、プロセスは成立します。** どれか欠けたままデプロイすると、エンジン上で図が正しく動きません。接続するときはノードのコネクタから引きます。図形そのものをドラッグすると、移動するだけでつながりません。

### ステップ 6: エンジンへデプロイする

**このステップの目的**

キャンバス上の図をエンジンに渡します。デプロイされたプロセスだけが実行できます。

**実行する操作**

1. 左下のビュー切り替えを `開発ビュー` にします。
2. キャンバス右上のツールバーで `デプロイ` をクリックします。
3. 「エンジンにデプロイ」ダイアログで、エンジンアドレスとデプロイ内容（現在のプロセス）を確認します。
4. `デプロイ` をクリックします。

**確認できること**

ダイアログが閉じ、成功のメッセージが表示されます。左のツリーの `実行` セクションに、このプロセス定義が追加されています。

**ここに注目**

`デプロイ` は開発ビューにだけ現れ、設計ビューには出てきません。権限の問題ではなく、2 つのビューが別の利用者を想定しているためです。また、デプロイが送るのは常に**いまキャンバスにある内容**で、最後に保存した時刻とは関係ありません。

### ステップ 7: 実行を開始する

**このステップの目的**

実際に 1 回動かし、実行モジュールでインスタンスを確認します。

**実行する操作**

1. `実行` モジュールを開き、左側で `プロセス定義` を選びます。
2. いまデプロイしたプロセスを探し、`プロセスを開始` をクリックします。
3. ウィザードの各画面を確認します。どこから開始するか、ビジネスキーと変数、開始オプション。
4. `開始` をクリックします。

**確認できること**

ウィザードが閉じ、開始結果とプロセスインスタンスへのリンクが表示されます。プロセスインスタンスの一覧では、この実行がアクティブとして並び、開始イベントの直後のタスクでハイライトされています。

**ここに注目**

開始時に問われるのは 3 つで、順番は決まっています。**どこから始めるか、何を渡すか、どう実行するか。** 指示を入れなければ、描いた本線という既定の経路を通ります。

## 4. 作ったものの振り返りと次への一歩

ここまでを一度振り返ります。

| 作ったもの | 解決していること |
| :--- | :--- |
| ワークスペース | この仕事を他の人たちの仕事と切り離す |
| 業務アプリ | 1 つの業務ラインのプロセス・フォーム・コネクタを 1 か所にまとめる |
| BPMN プロセス | 「誰がいつ何をするか」をエンジンが実行できる形にする |
| デプロイ記録 | エンジンにこのプロセスを認識させ、版を残す |
| プロセスインスタンス | 実際に起きた 1 件の業務を追跡し、手を入れられるようにする |

このプロセスはまだ素朴です。タスクが 1 つ、分岐が 1 つで、フォームもコネクタもエージェントもありません。それらはこの幹に育っていきます。

- キャンバス右側の `AI アシスタント` は、「承認ゲートウェイと承認・却下分岐を追加」のような一言で要素を作成し接続します。読むのも変えるのも現在のキャンバスです。
- ノードに必要なフォーム、決定、コネクタは、ノードを選択したときのプロパティパネルから取り付けます。
- プロセスドキュメントとノードコメントはモデルと一緒に保存されるので、設計意図を残す場所として適しています。

連携の細部はまだ見なくて大丈夫です。このプロセスを外部システムにつなぎたくなったときに、[HTTP コネクタ](/ja/reference/connector/http/) と [BPMN モデラー画面](/ja/reference/bpmn/modeler/) を開けば間に合います。

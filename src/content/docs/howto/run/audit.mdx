本篇覆盖两个治理面板：**用户操作日志**回答「谁在什么时候改了什么」，**历史清理**回答「数据留多久、怎么删」。

## 用户操作日志

### 1. 查询操作记录

**前置条件**
* 已登录 ORION，从顶部「打开应用菜单」进入「运行」。

**操作步骤**
1. 在左侧导航点击「用户操作日志」。
2. 点「筛选」打开面板，按需填写：
   * **常规**：操作人、操作类型、对象类型、分类、变更字段、时间晚于 / 时间早于；
   * **作用对象**：流程实例 ID、流程定义 ID、流程定义 Key、执行流 ID、任务 ID、作业 ID、作业定义 ID 等。
3. 点「重置」清空条件；点「刷新」拉取最新记录。

**预期结果**
* 列表按时间排序展示时间、操作人、操作、对象、变更与备注六列。
* 修改条件后结果自动更新。

### 2. 查看操作详情并加备注

**操作步骤**
1. 点击目标记录，右侧滑出「操作详情」。
2. 在「这次操作」区查看变更内容，在「标识与关联」区核对记录 ID、根流程实例 ID 与清理时间。
3. 需要留痕说明时，在「备注」区填写并保存。

**预期结果**
* 备注保存后回写到列表的备注列。
* 提示会说明：这是一条「改动备注」的留痕，不是业务数据变更。

## 历史清理

### 3. 查看清理任务状态

**操作步骤**
1. 在左侧导航点击「历史清理」。
2. 读取标题旁的状态标记：**已启用** 或 **已停用**。
3. 在列表核对每个清理任务的作业 ID、状态、到期时间、剩余重试与创建时间。

**预期结果**
* 启用时显示任务列表、总数与批处理窗口区间；剩余重试为 0 表示重试已耗尽，不会再运行。
* 停用时**列表照常显示已有任务**（引擎只是不再新建），顶部显示黄色横幅「本引擎已停用历史清理：不会自动删除任何历史数据，手动触发也会被拒绝。需要改引擎配置才能重新开启。」——横幅取代数量警告，两者不会同时出现。
* 停用且列表确实没有任务时，才显示空态「历史清理已停用，不会创建清理任务」。
* **启用**且有挂起或重试耗尽的任务时，顶部给出数量警告「有 `{N}` 个清理任务已挂起或重试耗尽，它们都不会再运行。」

### 4. 查看清理配置（只读）

**前置条件**
* 「配置」是**只读弹窗**：没有开关、没有输入框、也没有保存按钮——自动清理开关与批处理窗口都写在引擎配置里，要改需修改引擎配置文件。

**操作步骤**
1. 点击「配置」打开历史清理配置。
2. 核对 **自动清理** 当前状态（已启用 / 已停用）。
3. 核对 **批处理窗口**：已配置时列出窗口开始与窗口结束，并给出「此刻在窗口内」是/否；未配置时显示琥珀色的「未配置批处理窗口」。
4. 读完点「关闭」。

**预期结果**
* 弹窗底部说明：窗口未配置时，清理任务只会在「立即执行」时建立，否则什么都不会发生；本页只能查看，窗口要改引擎配置。
* 状态与窗口信息随面板数据刷新，不做任何本地修改。

### 5. 手动触发一次清理

**前置条件**
* 手动触发需要管理员权限；引擎停用历史清理时本操作不可用——「立即清理」按钮置灰，弹窗内也会提示「本引擎已停用历史清理，无法手动触发。」

**操作步骤**
1. 点击「立即清理」，阅读弹窗说明。
2. 按需勾选 **立即执行（不等待批处理窗口）**：
   * 勾选：任务排到最近的将来，马上会跑；
   * 取消勾选：排到下个批处理窗口开始时。
3. 点「执行清理」确认。

**预期结果**
* 成功时提示「已触发历史清理」或「已安排到下个批处理窗口」。
* 未配置批处理窗口且未勾选立即执行时，会给出手动排期的警告，按提示勾选后再执行。

:::danger[清理永久删除且不可撤销]
清理删除的是已超过保留期的历史数据：流程、决策、案例实例及相关历史，以及批处理与历史作业日志。执行前确认保留期设置符合合规要求。
:::

---
title: 如何查看进行时视图
description: 如何在 ORION 流程定义详情的进行时视图下逐个页签核对流程实例、故障、调用的流程与决策、Job 定义、人工任务与协作流程。
---

进行时视图看的是**此刻正在发生的事**：还在跑的实例、还没处理完的故障、当前版本上挂着的作业与人工任务。

页签栏依次为：流程实例、故障、调用的流程、调用的决策、Job 定义、人工任务、协作流程。每个页签右侧带各自计数。页面右侧「本页内容」目录列着这七个页签，点任意一项可直接跳到本页对应小节。

**前置条件**
* 已进入目标流程定义的详情页，并在工具栏最右端切到「进行时」，见 [如何切换视图、版本与刷新](/howto/run/process/view/)。

### 流程实例

**操作步骤**
1. 在页签栏点「流程实例」。
2. 快速定位：把流程实例 ID 粘贴进顶部输入框，列表自动查询——快速搜索优先于并叠加在高级条件之上。
3. 需要组合条件时点「设置查询条件」，按页签逐组填写（多个条件同时生效）：
   * **标识与定义**：实例 ID、ID 列表、排除 ID；定义 Key、名称包含、定义 ID；
   * **业务、状态与事故**：业务键、实例状态（不限状态、未结束、已结束、活跃、已挂起、已完成、外部终止、内部终止）、发起人、租户 ID，以及仅显示存在事故的实例；
   * **时间范围**：按时间收窄；
   * **关系与活动**：父子流程与 Case 关系、按当前节点收窄；
   * **变量与 OR**：按变量值收窄（专家选项）。
4. 核对条件后点「查询」；点「重置条件」清空全部条件，点「取消」关闭对话框。
5. 点列表中的实例行进入实例详情。

**预期结果**
* 列表列出实例 ID、业务键、状态、开始时间、结束时间与耗时；底部显示「共 `{条数}` 条结果」，修改条件后自动刷新。
* 页签标题上常驻一条迷你走势，反映当前页实例的起止趋势；点「地图」可在流程图上定位当前节点。
* 实例详情给出概览、变量、智能体、故障、调用的流程实例、Job工作、人工任务、外部任务等页签；变量页签在未选中实例时提示「选择一个流程实例以查看变量」。

### 故障

**操作步骤**
1. 在页签栏点「故障」。
2. 用「故障类型」「故障状态」两个筛选收窄。
3. 需要时点行内的「查看该实例详情」跳到对应实例。

**预期结果**
* 每行给出故障类型、故障信息、活动节点、状态与流程实例 ID，ID 可复制。
* 可为故障补写或修改备注，便于交接。
* 这里的记录对应实例上真正卡住的地方，排查路线见 [如何处理作业与线程池](/howto/run/job/)。

### 调用的流程

**操作步骤**
1. 在页签栏点「调用的流程」。

**预期结果**
* 列出这张图通过调用活动引出的外部流程：流程名、版本、状态、定义 ID，以及**调用的活动**（本图上是哪个节点发起的）。
* 点流程名可打开该流程定义的详情；点定义 ID 可复制。空态提示「这个流程定义没有调用其他流程」。

### 调用的决策

**操作步骤**
1. 在页签栏点「调用的决策」。

**预期结果**
* 列出这张图引用的决策表：决策、DRD、版本与定义 ID，并可打开对应决策定义。
* 只带决策引用的业务规则任务才会出现在这里；业务规则任务也可能走别的实现，此时页签给出说明。
* 图上写了引用不等于决策已部署——决策来自另外上传的决策文件，没部署时这里会给出提示而不报错。

### Job 定义

**操作步骤**
1. 在页签栏点「Job 定义」。
2. 用「按此作业类型筛选」收敛到某一类定时或异步作业。

**预期结果**
* 每行给出作业定义 ID、作业类型、活动节点、作业配置与挂起状态，ID 可复制。
* 这一格回答的是「这个版本上排了哪些作业」，具体某次执行的结果在 [如何查看历史视图](/howto/run/process/history/) 的 Job 日志里。

### 人工任务

**前置条件**
* 仅进行时视图提供这一格；历史视图下没有对应页签。

**操作步骤**
1. 在页签栏点「人工任务」。
2. 用列头排序，或点「按这个…筛选」收敛范围。
3. 需要时点行内动作直接处理任务：完成、认领、转派、上报业务错误或升级。

**预期结果**
* 列出任务名、办理人、创建时间、截止时间、优先级、状态与所属实例。
* 可点「在图上高亮」看它落在流程图的哪个节点，也可点「查看该实例详情」跳到实例。

### 协作流程

**操作步骤**
1. 在页签栏点「协作流程」。

**预期结果**
* 一行是同一张协作图上**另一个泳池**指向的流程定义，按泳池在图上的顺序排列：流程名、版本、状态与定义 ID。
* 这一格读的是已部署的模型，历史视图下内容完全一致。
* 池可以先画、后部署；指向的流程定义还没部署时会给出提示而不报错。

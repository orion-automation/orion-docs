能力中心维护可被业务应用引用的组件：连接器、外部执行器、技能、智能体、模型与智能文档处理。本篇覆盖组件的增删改与上下架，以及每类组件的设置项与流程用法。

## 1. 进入能力中心并定位分类

**前置条件**
* 已登录 ORION，从顶部「打开应用菜单」进入「设计」。

**操作步骤**
1. 在左侧导航点击**能力中心**。
2. 顶部页签在六个分类间切换：**连接器**、**外部执行器**、**技能**、**智能体**、**模型**、**智能文档处理**。
3. 需要定位时用搜索框输入关键词。

**预期结果**
* 列表显示当前分类下的组件，列包含组件名称、描述、标签、状态、版本、最后更新时间与操作。
* 表尾显示总数「共 `{total}` 个组件」。
* 搜索无结果时提示「未找到匹配的组件」，并建议「尝试更换关键词或切换到其它分类」。

## 2. 创建组件

**操作步骤**
1. 切到目标分类。
2. 在创建输入框中输入组件名称。
3. 点击**创建**。

**预期结果**
* 组件以**草稿**状态进入列表，之后可继续配置与发布。
* 名称为空或创建失败时提示「创建失败，请重试」，修正后重试即可。

## 3. 发布与取消发布

**操作步骤**
1. 在目标组件行点操作菜单。
2. 选择**发布**，在确认框中核对影响后确认。
3. 需要下架时，同一菜单选择**取消发布**并确认。

**预期结果**
* 发布后组件状态变为**上架**，提示「发布后『`{name}`』将上架，可被工作空间中的业务应用引用。」
* 取消发布后回到**草稿**，提示「『`{name}`』将下架回到草稿状态，已引用它的业务应用可能失效。」——下架前先确认没有业务应用在引用它。
* 操作失败分别提示「发布失败」「取消发布失败」，可重试。

## 4. 重命名与移除

**操作步骤**
1. 行操作菜单 → **重命名**，输入新名称后点**保存**。
2. 行操作菜单 → **移除**，在确认框中核对后确认。

**预期结果**
* 重命名成功后列表立即刷新；失败提示「重命名失败」。
* 移除的提示为「移除后『`{name}`』将不可恢复，请谨慎操作。」，确认后组件从列表消失；失败提示「移除失败」。

:::danger[移除不可恢复]
移除会连同组件配置一起删除，且没有回收站。仅对确定不再使用的组件执行。
:::

## 5. 识别内置与未开通分类

**操作步骤**
* 观察组件行上的标记与页签状态。

**预期结果**
* 标记为**内置**的组件是系统预置的，不参与上面的发布/移除流程。
* 分类未开通时显示**锁定未激活**，提示「当前租户未开通该组件类型，如需使用请联系管理员」——该分类暂时只能查看，不能创建与修改。

## 6. 连接器

<details>
<summary>设置项与流程用法</summary>


**前置条件**
* 已在「连接器」分类创建组件并点击组件行进入详情页。

**操作步骤**
1. 详情页顶部页签：**基本信息**、**参数**、**请求头**、**请求体**、**响应**、**调用计划**。
2. **基本信息**页签填组件名称、说明、标签、版本标签——这些是组件记录字段，不属于接口配置。
3. **详细设置**里逐项配置：
   * **方法**与**接口地址**——地址引用流程变量写 `${orderId}`，变量名在下方表格把该行「来源」设为「流程变量」；
   * **请求头模板**、**查询参数模板**——每行是「名字 + 值 + 来源（常量或流程变量）」；
   * **路径参数**——由接口地址中的 `${名字}` 占位符自动生成，无需手动新增；
   * **请求体字段**——按字段录入会合并为一个 JSON 对象；要精确控制类型请用**请求体模板**；
   * **状态码存入变量**——把实际返回的状态码存进该流程变量（如 200 / 404），留空不写回；
   * **响应体字段**——声明「响应字段 → 流程变量」的映射，响应字段填 JSON 路径（如 `data.orderId`，填 `statusCode` 则取 HTTP 状态码），未声明映射时仍可获取完整响应体。
4. 保存前可在**调用计划**页签核对这份配置被流程设计引用时编译出的形状（只读）。

**预期结果**
* **参数**页签的实时预览显示「这份配置运行时发出去的请求」：方法、编译后的地址与各参数条数。
* **在流程设计中**：
  1. 先把连接器放进业务应用——连接器目录「更多操作 → 从AI 能力中心导入」，或在应用内新建；
  2. 画布上选中服务任务 → 属性面板「常规」分组的**快速设置**下拉选中它，一次写入整条实现；或在「添加元素」面板的**连接器**页签点击，画布直接落一枚已绑定该连接器的服务任务（任务名自动取组件名）。

</details>

## 7. 外部执行器

<details>
<summary>Topic、输入变量与流程接入</summary>


**前置条件**
* 已在「外部执行器」分类创建模板并进入详情页。

**操作步骤**
1. **基本信息**页签填说明、标签、版本标签。
2. **配置信息**页签填写：
   * **Topic 名称**（必填）——对应 BPMN 中 External Task 节点的 Topic 值，例如 `process-order`；只能含字母、数字、下划线、点、冒号和横线；
   * **输入变量**表逐行录入——对应 External Task 节点的输入变量，运行时作为局部变量传给 Worker：**变量名**（落到引擎侧的局部变量）、**显示名**（给人看的名字，如「订单编号」，不会写进流程）、**必填**（勾选后没填值会作为问题报出来）、**取值方式**（常量 / 变量 / 表达式 / 脚本）与**值**。
3. 用**导入** / **导出**按钮在机器间搬模板（导出文件带 `orionWorkerTemplate` 标记；应用资源的 `.orion-worker` 是运行时定义，两者不能互换）。

**预期结果**
* 保存前的预览「这一步会发给引擎什么」显示最终 Topic 与各参数；填几个示例值就能看到变量 / 表达式会解析成什么。
* **在流程设计中**：
  1. 画布上放置 External Task 类型的服务任务，属性面板「常规」分组的**快速设置**下拉切到「能力中心」页签选中该模板（无需先导入应用；两边都有内容时才出现页签，只有一边时直接显示列表）；
  2. 节点顶部的**模板参数**区显示同步状态——「与模板一致」，或提示「主题与模板不一致（模板：`{topic}`）—— 对不上的话引擎永远不会派发这个节点」，可点**对齐主题**或**补齐**一键修正，点**在能力中心打开**跳回模板。

</details>

## 8. 技能

<details>
<summary>定义 Key、触发规则与参数契约</summary>


**前置条件**
* 已在「技能」分类创建技能并进入详情页。

**操作步骤**
1. 详情页顶部页签：**基本信息**、**触发规则**、**编排**、**调用计划**。
2. **基本信息**核对**技能定义 Key**——它自动取自编排页签的流程 ID，这里不能直接修改；两处是同一个值，在**编排**页签的画布上改流程 ID 即可（未起名时点**去编排页签起名**）。
3. **触发规则**页签三段各写若干行（一行一条）：
   * **适用场景**——什么情况下该用这个技能，例如「员工入职办理」「采购申请审批」；
   * **禁止场景**——什么情况下不该用；若应交给别的技能处理，写明交给哪一个；
   * **约束规则**——使用时必须遵守的规定，例如「金额超过 10 万元需二级审批」。
4. **参数契约**两表：**入参契约**（调用时交给流程的变量）与**结果契约**（技能返回的变量），左边是技能对外声明的字段名，右边是背后流程里接收 / 产出它的变量名，留空即与字段名同名。
5. **编排**页签设计技能自己的流程；**调用计划**页签只读查看它被编排器引用时编译出的形状。

**预期结果**
* **在流程设计中**：技能经由智能体被流程调用——在智能体详情的**技能**页签点**添加**，搜索技能名称、定义 Key 或描述后选入；流程侧按**技能定义 Key** 引用它。

</details>

## 9. 智能体

<details>
<summary>行为、模型、技能与输出</summary>


**前置条件**
* 已在「智能体」分类创建智能体并进入详情页。

**操作步骤**
1. 详情页顶部页签：**基本信息**、**行为**、**模型**、**技能**、**输出**、**调用计划**。
2. **行为**页签：
   * **人设与指令**三段——**擅长什么**（一句话说清它负责的范围）、**怎么做事**（步骤与硬性约束）、**语气与边界**（口吻、价值观与明确不要做的事）；
   * **接入方式**——**对话**（用户在对话入口直接交谈，谁能用由专属权限组成员决定，成员在「组织 › 组」中维护）、**API**（由外部系统接口调用）、**Workflow Agent Task**（由流程里的 Agent 任务节点调用）；
   * **运行时**——**Agent 调用流程**默认是平台内置的智能体运行时，也可填自定义的 BPMN 流程定义 Key（须已在目标引擎中部署）；**最多推理轮次**（一轮 = 推理一次 + 执行一个技能，到顶那一轮不再调用技能、转人工接手），预设三档：常规业务 Agent、多 Skill 协作 Agent、复杂研究型 Agent；
   * **运行限制**——最大模型调用次数、最大工具调用次数、最大 Token 消耗、最大执行时长，留空 = 不限制；超限时 Agent 停止后续调用，把 ERROR 决策交回流程。
3. **模型**页签点**导入模型**从模型记录选一份，按需开**结构化输出**、勾**能力声明**、选**返回方式**（Streaming / Blocking）。
4. **技能**页签点**添加**挂上它能动用的技能。
5. **输出**页签选**输出格式**（纯文本 / Markdown / JSON / 变量清单），配**输出示例**、**输出变量**与**输出说明**，按需允许 ORION AI 润色回答。

**预期结果**
* **在流程设计中**：
  1. 画布「添加元素」面板 → **增强元素**页签 → 点**智能体任务**（自动调用 `ORION_AgentCall_Basic`）；
  2. 选中该节点 → 属性面板「调用活动」分组的**智能体资源**快速选择里选具体智能体——一次写入引用与它包装的各技能必填入参，之后改能力中心的配置无需回画布重选。

</details>

## 10. 模型

<details>
<summary>接入参数与协议配置</summary>


**前置条件**
* 已在「模型」分类创建接入并进入详情页。

**操作步骤**
1. 详情页顶部页签：**基本信息**、**接入参数**（页签上显示「必填项已填 `{filled}` / `{total}`」）。
2. **接入参数**逐项填写：
   * **供应商**——自由文本，例如 官方服务 / 私有化部署；
   * **模型**列表——一个接入可挂多个模型，点**添加模型**；**模型名**必填且不能重复（流程按模型名引用），显示名可选；
   * **接入地址（Base URL）**——兼容 OpenAI 协议的服务填到 `/v1` 为止，不要带 `/chat/completions`；
   * **API 密钥**——粘贴服务方签发的密钥，明文保存在这条记录的配置里；
   * **温度**、**单次最大输出**、**上下文窗口**（模型一次能读入的 token 数，不出现在请求里）；
   * **推理强度**——关闭思考 / 低 / 中 / 高 / 最高，档位越高思考越久，不指定则不发送；开启后温度将被忽略；
   * **协议风格**——OpenAI 兼容 / Anthropic Claude / Google Gemini / Azure OpenAI / 自定义内网网关（内网网关一般选「OpenAI 兼容」）；**对话路径**留空则按协议风格自动推导；**API 版本**填在路径查询串里而非请求头；**超时（毫秒）**与 ORION 侧任务超时对齐，避免流程实例被长期占住；
   * **高级设置**——**额外请求头**（JSON 对象文本，网关 / WAF 要求的自定义头写这里）、**额外请求体字段**（并入每次请求体）、**能力声明**（对话 / 视觉 / 工具调用 / JSON 模式，用于流程编排按能力筛模型；不勾选只代表「未声明」）。
3. 用顶栏**测试**按钮选一个模型实发一次请求，验证配置能否调通。

**预期结果**
* **在流程设计中**：模型不直接上画布——智能体与智能文档处理的**模型**页签点**导入模型**引用它；流程节点按**模型名**引用模型，所以模型名不能重复。

</details>

## 11. 智能文档处理

<details>
<summary>接入配置、提示词与输出</summary>


**前置条件**
* 已在「智能文档处理」分类创建配置并进入详情页。

**操作步骤**
1. 详情页顶部页签：**基本信息**、**接入配置**、**模型**、**提示词与输出**、**调用计划**。
2. **接入配置**页签：
   * **Topic 名称**——BPMN 里 External Task 节点填的 Topic，必须与 Worker 订阅的一致；留空即用默认值；
   * **允许的文件类型**——只解析勾选的类型，其余在调用时被拒绝；一种都不勾会提示「一种文件类型都没勾，这份配置什么都处理不了。」；
   * **文件限制**——**单文件上限**、**单次合计上限**、**页数上限**；超过任一上限的文件直接拒绝、不进入解析（避免一次调用把费用和时延拖爆），PPTX 的「页数」是幻灯片数。
3. **模型**页签与智能体同一套绑定（**导入模型**）。
4. **提示词与输出**页签：
   * **System Prompt**——模型的角色与硬性要求；文档内容会被当作不可信输入，不会覆盖这里的指令；
   * **提取 Prompt**——要抽什么、怎么判断；解析出的文档正文会接在这段话后面一起发给模型；
   * **输出 JSON Schema**——模型返回的 JSON 由程序按它实际校验，不合规就是失败，不会当成成功结果；点**格式化**整理排版。
5. **执行**里设**模型调用超时**（秒）与 **JSON 修复重试**（不重试 / 重试 1 次 / 重试 2 次）——输出不合格时回传校验错误要求模型重新生成，次数用尽仍不合格则本次执行判定为失败。

**预期结果**
* **在流程设计中**：
  1. 画布上放置 External Task 类型的服务任务，属性面板「常规」分组的**快速设置**下拉切到「能力中心」页签选中这条记录（两边都有内容时才出现页签，只有一边时直接显示列表）；
  2. 节点顶部的**智能文档处理**区填**文件变量**——流程变量名（如 `invoiceFile`），运行时至少需要一个引擎中的文件类型流程变量；只能填变量名、不能是表达式，且当前仅支持一个；未发布或 Schema 无效时分别提示「还没发布」「Schema 无效」。

</details>

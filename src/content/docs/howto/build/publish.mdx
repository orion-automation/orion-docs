编辑完成后的两条上行路径：**发布评审**把版本送进审批流程，**部署**把当前内容推送到引擎。两者入口不同、前置条件不同，本篇分别说明。

## 1. 提交发布评审

**前置条件**
* 目标资源是**编排目录下的流程**或**决策目录下的决策**，且已保存到服务端。
* 引擎上已部署 ORION 的审批流程（未部署时提交会被拒绝，见下方预期结果）。

**操作步骤**
1. 在业务应用文件树中，悬停目标资源行，点「更多操作」→ **发布**。
2. 系统先保存该资源的当前内容（有未保存改动时会先落库），再打开**发布评审**对话框。
3. 确认**流程**名称，选择**发布版本**。
4. 选择**基准版本**用于差异对比；默认取前一版本，可改选其他版本，当前正在编辑的版本带「当前编辑版本」标记。
5. 选择**审核范围**：
   * **仅变更部分**（默认）——只审改动涉及的泳道；
   * **全局**——整条流程送审。
6. 核对差异摘要：**新增**、**删除**、**修改**、**布局**四类计数。
7. 点击**提交发布**。

**预期结果**
* 提交成功提示「发布评审已提交」，审批流程随之在引擎上启动。
* 审核范围为「仅变更部分」时，BPMN 会显示送审规模：「涉及 `{lanes}` 条泳道，将送 `{count}` 位审核人」；变更涉及的泳道与流程 owner 都没登记责任人时提示「变更涉及的泳道与流程 owner 都还没登记责任人」——先到责任登记补齐再送审。
* 引擎上还没有审批流程时，提交被拒并提示「审批流程 `{key}` 尚未部署」——先部署审批流程再回来提交。
* 资源还没有版本记录时提示「这个资源还没有版本记录」；只有一版没有可对比版本时显示「无可对比版本」，基准为空则整条流程按「新增」对待并给出说明。
* 这一版里没有流程图时提示「这一版里没有流程图，没有东西可以发布」；两版一致时显示「两版没有差异」。
* 差异计算或版本列表读取失败会给出带原因的提示（如「差异计算失败：`{message}`」），可重试。

:::note[发布 ≠ 部署]
发布评审走的是**审批流程**，产出的是「谁审过哪一版」的记录；引擎要真正按这版运行，还需要完成下方的部署。
:::

## 2. 部署到引擎

**前置条件**
* 在「我的引擎」中至少配置了一台引擎（见[如何维护我的引擎](/howto/build/engines/)）。
* 当前流程或决策有可部署的内容（画布为空时无法提交）。

**操作步骤**
1. 在流程编辑器工具条上点击**部署**（决策编辑器同样在工具条上）。
2. 在**部署到引擎**对话框中，于**部署引擎与认证**区选择目标引擎：
   * 引擎清单来自「我的引擎」，默认选中带「默认」标记的那台；
   * 下方只读显示所选引擎的**引擎地址**与**基本认证**（没配认证时显示「不使用认证」）。
3. 在**部署内容**区确认首行的**当前流程**（决策为「当前决策」），可选：
   * 点**拖入文件，或点击选择（可多选）**追加同批文件；
   * 与当前流程同名的追加文件会被跳过，提示「`{name}` 与当前流程文件同名，已跳过」；
   * 不需要的追加行点**移除**。
4. （可选）填写**部署名称**。
5. 点击**部署**，等待完成。

**预期结果**
* 成功提示「`{name}` 已部署」，按钮在过程中显示「部署中…」。
* 「我的引擎」里还没有引擎时空态提示「『我的引擎』里还没有配置引擎」，并说明先去新增一台引擎（地址以及需要的用户名和密码）再回来部署；对话框内有**打开「我的引擎」**的直达入口。
* 没选引擎就提交时提示「请先选择一个部署引擎。」；画布没有内容时提示「这张图还没有可部署的内容」（决策为「这张决策模型还没有可部署的内容」）。
* 各类失败都指明到「我的引擎」改哪一项：
  * 读不到本机保存的认证信息 → 重新填写并保存这台引擎的用户名和密码；
  * 地址不是有效的 http(s) 地址 → 修正引擎地址；
  * 认证失败（401/403）→ 检查用户名和密码，并确认账号有部署权限；
  * 地址上找不到引擎接口（404）→ 检查地址应填引擎根地址（不要包含 `/engine-rest`）；
  * 连不上（网络错误、跨域被阻止或请求超时）→ 检查地址、服务是否可用以及是否允许当前站点跨域访问；
  * 引擎拒绝部署（其他 HTTP 状态）→ 检查引擎配置或联系它的管理员。

## 3. 部署后在哪确认

**操作步骤**
1. 回到业务应用左侧文件树，展开**运行**段。
2. 在「运行引擎」下拉中选择刚部署到的那台引擎。

**预期结果**
* 刚部署的流程定义出现在清单中；展开可看到它的流程定义 Key。
* 点击 Key 行在新标签页打开运行模块的流程定义详情，可继续查看实例与执行情况。
* 该工作空间的实例统计同时出现在工作空间详情的「测试运行」页签（见[如何管理工作空间详情](/howto/build/workspace-detail/)）。

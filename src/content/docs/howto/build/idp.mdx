**前置条件**
* 已在「智能文档处理」分类创建配置并进入详情页。

**操作步骤**
1. 详情页顶部页签：**基本信息**、**接入配置**、**模型**、**提示词与输出**、**调用计划**。
2. **接入配置**页签：
   * **Topic 名称**——BPMN 里 External Task 节点填的 Topic，必须与 Worker 订阅的一致；留空即用默认值；
   * **允许的文件类型**——只解析勾选的类型，其余在调用时被拒绝；一种都不勾会提示「一种文件类型都没勾，这份配置什么都处理不了。」；
   * **文件限制**——**单文件上限**、**单次合计上限**、**页数上限**；超过任一上限的文件直接拒绝、不进入解析（避免一次调用把费用和时延拖爆），PPTX 的「页数」是幻灯片数。
3. **模型**页签与智能体同一套绑定（**导入模型**）。
4. **提示词与输出**页签：
   * **System Prompt**——模型的角色与硬性要求；文档内容会被当作不可信输入，不会覆盖这里的指令；
   * **提取 Prompt**——要抽什么、怎么判断；解析出的文档正文会接在这段话后面一起发给模型；
   * **输出 JSON Schema**——模型返回的 JSON 由程序按它实际校验，不合规就是失败，不会当成成功结果；点**格式化**整理排版。
5. **执行**里设**模型调用超时**（秒）与 **JSON 修复重试**（不重试 / 重试 1 次 / 重试 2 次）——输出不合格时回传校验错误要求模型重新生成，次数用尽仍不合格则本次执行判定为失败。

**预期结果**
* **在流程设计中**：
  1. 画布上放置 External Task 类型的服务任务，属性面板「常规」分组的**快速设置**下拉切到「能力中心」页签选中这条记录（两边都有内容时才出现页签，只有一边时直接显示列表）；
  2. 节点顶部的**智能文档处理**区填**文件变量**——流程变量名（如 `invoiceFile`），运行时至少需要一个引擎中的文件类型流程变量；只能填变量名、不能是表达式，且当前仅支持一个；未发布或 Schema 无效时分别提示「还没发布」「Schema 无效」。

<p class="lead">
  在这篇教程里，我们将共同构建出一个能跑起来的业务流程：从创建工作空间开始，一路走到画布上的流程图，再把它部署到引擎、启动一次真实的运行。全程不需要写一行代码。
</p>

## 1. 概览与最终成果

我们要走完的是一条完整链路，共七步：

| 步骤 | 我们做的事 | 做完之后手上多出来的东西 |
| :--- | :--- | :--- |
| 1 | 创建工作空间 | 一个工作空间，里面已经有一个业务应用 |
| 2 | 进入工作空间 | 该空间的业务应用清单 |
| 3 | 打开业务应用 | 设计与发现资源的工作台 |
| 4 | 新建流程 | 一张带着泳池、泳道和开始节点的画布 |
| 5 | 把流程画出来 | 一条有分支、连得通的流程 |
| 6 | 部署到引擎 | 引擎上的一条部署记录 |
| 7 | 启动一次运行 | 一个正在跑的流程实例 |

三步之间有明确的因果：**工作空间装业务应用，业务应用装流程，流程部署之后才能运行。** 记住这条线，后面每一步点在哪里都不会迷路。

## 2. 前置准备

<Aside type="note" title="开始之前">

- 已经登录 ORION，并且能进入「设计」模块
- 你的账号在工作空间里拥有创建权限

如果进入「设计」后看到的是「当前账号无法创建工作空间」，说明账号配置还不完整，需要先联系系统运营管理方处理，后面的步骤都走不下去。

</Aside>

## 3. 详细实操步骤

### 步骤 1：创建工作空间

**我们的目标**

建一个容器。工作空间是这个产品里最外层的一格，业务应用、流程、表单、连接器最终都装在里面。

**具体执行动作**

1. 进入「设计」模块，停在「我的工作空间」。
2. 点击右上角的 `创建工作空间`。
3. 在弹窗里填写 **工作空间名称**，例如「订单履约」。
4. 同一个弹窗里还有 **初始业务应用名称**。它会替你建好第一个业务应用，默认填的是「业务流程应用」，我们保持默认。
5. 点击 `创建`。

**预期反馈**

弹窗关闭，列表里出现刚建好的工作空间，当前账号出现在协作人一栏。同时，一个名为「业务流程应用」的业务应用已经在该空间里就位。

**关键聚焦引导**

请注意，我们**没有**单独创建业务应用的步骤。这个产品的设计是让第一次进来的人少走一步：建空间的同时把第一格也铺好。后面所有流程都挂在这个业务应用下。

### 步骤 2：进入工作空间

**我们的目标**

进入刚建好的那一格，看到它里面的内容。

**具体执行动作**

在列表里点击刚才那一行工作空间的名称。

**预期反馈**

页面切换到工作空间详情，「业务应用」页签下能看到「业务流程应用」那一行。

**关键聚焦引导**

列表的列告诉我们这个空间里有多少东西：业务应用数、协作人、创建时间与最后更新时间。以后要判断「这个空间是不是我上次那个」，看最后更新时间最快。

### 步骤 3：打开业务应用

**我们的目标**

进入业务应用，看到它的资源结构。

**具体执行动作**

点击「业务流程应用」那一行。

**预期反馈**

左侧出现三个分段的树：`发现`、`设计`、`运行`，右侧是工作区。

**关键聚焦引导**

左侧三段对应三类工作：`发现` 放现状梳理的素材与结论，`设计` 放我们要画的东西，`运行` 列引擎上已经部署的流程。三段默认都是展开的，如果有哪一段被收起来了，点段头即可展开。

### 步骤 4：新建流程

**我们的目标**

得到一张空白画布，并且它已经自带泳池、泳道和开始节点。

**具体执行动作**

在 `设计` 段下找到放流程的那个目录，点击工作区空态卡片上的 `新建流程`。

**预期反馈**

画布打开，绘图区里已经有一个泳池、池里有一条泳道，泳道左端是一个名为「开始」的开始节点。

<Aside type="tip" title="观察重点">

在这个界面里，流程所在的目录有两个名字：默认的 **设计视图** 下叫「蓝图」，切到 **开发视图** 之后叫「编排」。同一个目录，同一批文件，只是叫法跟着视图改。找不到目录时先看左下角当前是哪一档。

</Aside>

### 步骤 5：把流程画出来

**我们的目标**

把这张图补成一条真正能跑的流程：有任务、有分支、有终点，而且每个框都连起来。

**具体执行动作**

1. 在画布左上角的建模托盘里点一下 `普通任务`，再点进泳道，把它放在开始节点右侧。
2. 同样从托盘里选 `排他网关`，放在任务右侧。
3. 再放一个 `普通任务`，作为通过分支上的下一步。
4. 放一个 `结束事件`，接在任务之后。
5. 从开始节点右端的连线点拖到任务上，再依次把后面的节点连起来。分支那两条从网关各拖一条线出来。

**预期反馈**

画布右下角的通关清单依次被勾上：泳池、泳道、开始节点、结束节点、任务、网关，最后是「每个节点都连起来了」。全部勾满时，这条流程就算画好了。

**关键聚焦引导**

清单不是给教程看的装饰，它是产品的判断依据：**清单全绿，流程才算成立。** 少任何一项，后面部署出去的图在引擎上都会出问题。加连线时留意，连线要从节点的连接点拖出，直接拖动整个节点只会挪位置。

### 步骤 6：部署到引擎

**我们的目标**

把画布上的这张图交给引擎。只有部署过的流程，才能被启动。

**具体执行动作**

1. 看左下角的视图开关，切到 `开发视图`。
2. 在画布右上角的工具栏里点击 `部署`。
3. 在「部署到引擎」窗口里确认引擎地址与部署内容，内容是「当前流程」。
4. 点击 `部署`。

**预期反馈**

窗口关闭并给出成功提示。回到业务应用的左侧树，`运行` 段下多出这条流程的定义。

**关键聚焦引导**

`部署` 这个入口只在开发视图下出现，设计视图里看不到它 —— 这不是权限问题，是这两档视图各自服务的人不同。另外，部署下发的永远是**当前画布上的内容**，与上次保存是什么时候没有关系。

### 步骤 7：启动一次运行

**我们的目标**

让它真的跑一次，并在运行模块里看到这个实例。

**具体执行动作**

1. 进入 `运行` 模块，在左侧选择 `流程定义`。
2. 找到刚才部署的那条流程，点击 `启动流程`。
3. 按向导逐屏确认：从哪个节点开始、要不要填业务键与变量、启动选项。
4. 点击 `启动`。

**预期反馈**

向导收起并给出启动结果，附一个前往流程实例的入口。在 `流程实例` 里能看到这条正在运行的记录，状态为活动，并且高亮停在开始节点之后的那个任务上。

**关键聚焦引导**

启动这一屏有三个问题，顺序固定：**从哪开始、带什么参数、怎么执行。** 不填指令时就走流程的默认路径 —— 也就是你画的那条主线。

## 4. 成果复盘与展望

回看一次我们做过的事：

| 我们建了什么 | 它解决的问题 |
| :--- | :--- |
| 工作空间 | 把这件事和别人的事隔开 |
| 业务应用 | 把一条业务线的流程、表单、连接器收在一处 |
| BPMN 流程 | 把「谁在什么时候做什么」画成引擎能执行的形状 |
| 部署记录 | 让引擎认识这条流程，并留下版本 |
| 流程实例 | 一次真实发生的业务，可以被跟踪、被干预 |

这条流程还很朴素：只有一个任务和一个分支，没有表单、没有连接器、没有智能体。它们都是在这条主干上长出来的：

- 画布右侧的 `AI 对话助手` 可以直接用一句话创建和连接元素，例如「添加审批网关和通过、拒绝两个分支」。它读的是当前画布，改的也是当前画布。
- 节点需要的表单、决策、连接器，都在选中节点后的属性面板里挂上去。
- 流程文档与节点评论随模型一起保存，适合把设计意图留下来。

接口层面的细节不必现在就看。等我们要把这条流程接到外部系统时，再看 [HTTP 连接器](/reference/connector/http/) 与 [BPMN 建模器界面](/reference/bpmn/modeler/) 也来得及。
